# 华为运动健康：Android 接入准备与验收

核验日期：2026-10-20。目标是个人 Android 应用读取用户自己的睡眠和运动数据。本文区分本机代码事实、官方已确认的流程，以及必须由目标账号或设备确认的条件；没有登录开发者账号、提交申请或读取个人健康数据。

## 1. 当前交付到哪里

| 项目 | 当前事实 |
| --- | --- |
| Android 包名 | `dev.tracelife.app`，见 `app/build.gradle.kts`。 |
| 健康看板 | 已有睡眠时长、运动分钟数的卡片类别；状态仍为 `SOURCE_NOT_CONNECTED`。记录覆盖率、手动学习和工作指标不代表设备健康数据。 |
| 设备健康数据主存 | 尚无华为样本、同步游标、去重和来源修订的数据模型；普通记录主存不能直接等同于已完成健康接入。 |
| 华为连接 | 尚未加入 HMS Health / Account SDK、AGC 构建配置、登录授权、读取或撤销授权处理。现有 APK 无法靠填一个 KEY 开始同步。 |
| 开发者资格与服务权限 | 未登录目标开发者账号，未核实 Android 申请资格、已批准的数据权限或有效期。 |
| 真机验证 | 未在用户手机上验证 HMS Core、华为账号授权、运动健康分享授权和实际数据读取。 |

健康数据连接仍需实现；下述准备材料用于解除外部依赖，不能视为功能已经上线。长期知识库、手动记录、复盘和画像功能可以独立使用。

## 2. 用于注册的应用身份

2026-10-20 对本机 `app/build/outputs/apk/debug/app-debug.apk` 执行 `apksigner verify --print-certs`，签名校验成功，证书主体为 `C=US, O=Android, CN=Android Debug`。

| AGC 配置项 | 本机核验值 |
| --- | --- |
| 应用平台 | Android |
| 应用包名 | `dev.tracelife.app` |
| 当前调试 APK 的签名证书 SHA-256 | `E7:EC:2F:01:C2:74:0B:2D:94:3A:89:A9:15:1E:02:3C:5D:00:08:72:40:A1:4A:FF:E1:EE:B6:5B:23:AB:AB:73` |

这个值是可公开的**签名证书指纹**，不是 APK 文件哈希，也不是密钥。它只适用于使用这张调试证书签名的 APK；更换构建电脑、调试证书或改为正式签名后，必须从实际安装包重新取值并更新 AGC。不要索取或提交签名私钥、证书密码。

复核命令由 Android SDK Build Tools 提供：

```sh
apksigner verify --print-certs /absolute/path/to/the-apk-to-install.apk
```

AGC 的包名、登记指纹和实际安装包必须一致。后续若采用正式签名，需要先确定稳定的签名身份，再注册其指纹；本次没有创建正式签名。

## 3. 用户一次准备的非秘密信息

填写下面的状态和标识即可。无需提供账号密码、手机号、邮箱、验证码、访问令牌、真实健康明细或密钥。

| 信息 | 具体填写内容 | 用途 |
| --- | --- | --- |
| 手机 | 品牌、型号、系统名称及版本；华为运动健康版本；HMS Core 是否安装及版本 | 确认是 Android 接入链路，并确定后续兼容验证设备。不能只填“最新版”。 |
| 华为账号 | 注册国家／地区；运动健康与拟授权账号是否相同 | 核实服务地域及授权链路，不需要账号标识本身。 |
| 开发者身份 | 个人／企业、开发者认证完成与否 | 在 Android 控制台核对该身份可申请的服务，不套用其他平台规则。 |
| AGC 应用 | Project ID、App ID、平台 Android、包名、已登记证书指纹 | 对齐应用身份；这些公开应用标识不是访问令牌。 |
| Health Kit 申请 | 是否能选择 Android 应用、申请状态、获批的只读数据权限标识、测试／正式阶段、控制台明确显示的期限或账号限制 | 决定实际能读取的字段。若申请被阻止，记录不含个人资料的原始错误文字和对应 Android 官方说明链接。 |
| 穿戴设备与同步 | 手表／手环型号；最近是否成功同步；是否存在一条睡眠和一条运动记录及其日期 | 选定最小真机验收样本；不需要把数值或原始文件发到聊天。 |
| 配置位置 | 仓库外 `agconnect-services.json` 的绝对路径 | 后续开发时读取本机配置；不要贴出文件内容。 |

如果暂时没有开发者账号或申请入口不可用，明确写“未创建”“无 Android 入口”或实际阻断信息即可；这不同于设备没产生数据。

## 4. 开发者控制台操作顺序

1. 用户自行登录 [HUAWEI Developers](https://developer.huawei.com/consumer/) 并完成控制台要求的开发者认证；在 AppGallery Connect 创建项目和 **Android** 应用。登记上面的包名及实际 APK 签名 SHA-256。
2. 在项目设置的应用信息核对包名、App ID 和指纹；按所选 Android SDK 的准备说明启用必要 API。下载此应用的 `agconnect-services.json`。官方 HMS 准备说明包括应用注册、签名指纹和配置文件步骤；本仓库的文件存放约定见下节。[官方 HMS 接入准备](https://developer.huawei.com/consumer/en/codelab/HMSPreparation/index.html)
3. 进入开发者控制台的 Health Kit 申请入口，选择该 Android 应用，提交最小只读数据需求并记录审核状态。官方 Android SleepTracker 示例展示了申请入口、账号授权、运动健康分享授权，以及 `Scopes.HEALTHKIT_SLEEP_READ`；应用批准范围和用户授权范围共同限制可读数据。[官方 Android SleepTracker 示例](https://developer.huawei.com/consumer/en/codelab/SleepTracker/)
4. 将实际获批的 scope 标识、阶段和期限记入仓库外配置说明。只有申请通过和配置下载还不够；需要接入 SDK 并构建带连接功能的 APK 后，才能在手机完成用户授权。

本项目建议先申请以下最小数据集合。这是产品选择，不是已获批权限清单：

| 数据 | 首次目标 | 可选字段及限制 |
| --- | --- | --- |
| 睡眠 | 起止时间、时长 | 分期须确认对应权限和实际返回；运动健康界面的睡眠评分不能假定开放。 |
| 运动 | 运动记录类型、起止时间、时长 | 步数另行确认权限和统计口径；不把运动次数推算为分钟数。 |

除已核实的睡眠示例常量外，其余精确权限标识以 **Android 控制台和获批 SDK 文档**为准，不猜测名称。首轮不申请写权限、轨迹、心率等与上述目标无关的范围。SleepTracker 同时包含扫码和推送演示，其全部依赖和服务开关不应原样搬入本项目。

**Android 资格仍有证据缺口。** 本次访问 [Android 申请指南](https://developer.huawei.com/consumer/en/doc/HMSCore-Guides/apply-kitservice-0000001050071707)及对应中文页，得到抓取错误或只有文档外壳，没有取得资格正文。因此不能保证个人自用应用一定获批，也不能断言 Android 必须上架、测试用户数、审核天数或权限期限。后续以目标账号选择 Android 后的申请页面及官方答复为准。

[HarmonyOS JavaScript 申请指南](https://developer.huawei.com/consumer/en/doc/HMSCore-Guides/harmonyos-apply-kitservice-0000001194699502)和原子服务资格规则适用于其标明的平台，不作为本 Android 应用的资格证明。另外，[云侧订阅通知说明](https://developer.huawei.com/consumer/de/doc/HMSCore-Guides/subscription-0000001078496860)限制个人开发者申请该订阅能力；不能据此推导所有 Android 查询接口都禁止个人开发者。首轮方案采用 Android 端显式读取，不以云回调订阅为前提。

## 5. 配置文件保存在仓库之外

建议在开发电脑上使用以下目录；这是待接入时的存放约定，**现有程序尚未实现从这里加载**：

```text
~/.config/trace-life/huawei/
  agconnect-services.json   # 从目标 AGC Android 应用下载
  setup-notes.md            # 应用标识、权限状态、设备版本和配置核验日期
```

目录和文件只授予当前系统用户读取权限。后续构建应显式读取这个路径，把所需配置提供给构建流程；源配置不提交到 Git。当前 `.gitignore` 没有专门忽略 `agconnect-services.json`，所以现在不要按示例把文件放进 `app/` 后直接提交。此任务没有复制或读取任何实际配置文件，也没有修改构建来接入华为。

`setup-notes.md` 可以记录上述非秘密清单、获批 scope 和是否到期；账号登录凭据、令牌、签名私钥和服务端密钥均不写入其中。后续若某种服务确需服务端凭据，应另行设计凭据存储，不能装入 APK。

## 6. 接入实现后的手机验收

以下为待执行验收，不代表本轮已通过：

1. 在目标 Android 手机安装对应构建，确认 HMS Core 和华为运动健康可用。官方 Android 示例运行于安装 HMS Core 的手机；其旧版最低版本不能替代未来选定 SDK 的兼容范围。用户在手机自行完成华为账号登录，应用只请求获批的目标读权限。
2. 在华为运动健康确认穿戴设备数据已同步；第三方 Android 手机的官方参考入口为“我的 → 隐私管理 → 同步运动数据到云”，分享入口为“数据分享与授权”。菜单以手机版本实际显示为准。使用同一账号，并在必要时手动同步后再读取；穿戴数据到第三方存在延迟。[华为官方第三方同步排查](https://consumer.huawei.com/cn/support/content/zh-cn01115094/)
3. 选择最近一条睡眠及一条运动记录验证：来源、起止时间、时区、单位和权限范围正确；界面没有记录时区分“未授权”“没有该日数据”“尚未同步”“失败”，不把缺测显示成零活动。
4. 同一范围读取两次，确认主存去重和看板不重复计数；验证跨午夜睡眠、迟到同步和源数据修订。同步游标、失败恢复、修订传播、备份恢复以及图表下钻均须实现并通过验证。
5. 分别拒绝全部权限、只允许部分权限及撤销授权，确认停止读取、可见连接状态和明确的重新授权入口；重新安装／恢复备份不能自动恢复外部授权。断开连接与删除已保存的本地资料应是两个明确操作。
6. 健康原始资料接入已有受控检索、证据和预算流程后才能参与复盘。华为授权不等于授权把全部健康资料交给 DeepSeek；继续沿用应用已有的分析范围和用户授权边界。

达到“可用”的证据应同时包括：Android 服务权限确已获批、SDK 连接和健康主存实际实现、目标签名安装包成功授权、两种真实样本读取及上述失败场景通过。开发者控制台的通过状态、模拟器演示或手工合成样本都不能单独替代这项验收。
