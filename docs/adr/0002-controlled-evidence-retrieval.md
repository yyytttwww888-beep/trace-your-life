# ADR 0002：由执行层强制分层取证与校验发布

Trace Life 的资料持续增长，用户要求 AI 按需定位，不能一次接收全部知识库。
当前文档基线决定由应用执行层控制范围、快照、预算、证据覆盖与发布校验。
这个选择增加任务编排和取证成本，以换取可检查的范围、一致性及错误追溯。

本决定于设计阶段纳入项目文档基线，当时应用尚未实现；后续进度以[开发路线](../ROADMAP.md)为准。
它不指定模型、检索框架、向量数据库或 SDK，也不承诺自然语言分析不会出错。
详细规则见[分层检索与维护可靠性协议](../superpowers/specs/2026-10-16-knowledge-routing-and-reliability-design.md)。

## 决定及强制边界

逻辑入口为：全局入口 → 领域 → 时间或情境范围 → 证据目录 → 原始证据。
时间、主题、情境和稳定 ID 形成交叉索引，摘要用于定位，不能代替原始支持。
已知 ID 可在范围及状态验证后直接取证，不要求机械遍历全部层级。
后台整理、周期复盘和画像更新与用户查询遵守同一执行协议。

- 每项任务固定问题、范围、时间基准、来源快照、所需覆盖及读取预算。
- 模型只能使用受控取证接口，不能绕过它直接读取全库或改写权威资料。
- 执行层对每次实际模型输入计量，包括指令、历史、索引、工具结果和证据。
- 超出预算时分页或分批，并保存进度与缺口；不能静默截断后宣称完整。
- 处理台账细到原文片段与附件，读完开头不等于读完整条记录。
- AI 提交结构化分析或变更提案，程序检查通过后才保存和发布对应结果。

宽泛身份解释仍遵守[画像设计](../superpowers/specs/2026-10-16-long-term-personal-profile-design.md)的用户核对规则。
固定来源快照不豁免删除和用户反馈；当前删除状态始终优先。

## 不同问题采用不同证据策略

| 问题 | 必须采用的取证方式 |
| --- | --- |
| 精确查找 | ID、时间、来源、关键词与语义检索互补，命中后核对原文 |
| 趋势与全周期统计 | 程序对范围内全部合格数据作确定性查询和计算，保留口径、样本及排除条件 |
| 全周期文字分析 | 枚举完整范围并分批处理，未分类记录和未读附件不能被静默遗漏 |
| 长期画像与模式 | 跨周期及情境检查支持、反例和已有反馈，旧画像不能作为新增独立证据 |

语义检索的前几条命中不能代表整个周期，未命中也不能证明某件事不存在。
未知或不精确的发生时间单列未定范围，不以录入时间代替发生时间。
覆盖分别说明真实生活记录、任务取证范围和实际处理进度，不能合并成一个完成率。

## 综合、核对与发布

分批成果保留观察、引用、反例、未知项和来源版本；进一步综合仍保留回查路径。
实际输入按模型调用登记，整个任务中曾出现过某份资料不等于当前调用取得了它。
最终新结论核对原文、重要反例或确定性计算结果，不能只检查中间摘要。
程序检查引用及版本的有效性，语义核对检查引文是否支持结论及适用范围。
另一模型的同意不能代替真值；自然语言结果仍需可查看依据和纠正入口。

资料修订、补记、删除及时间窗口变化会使相关结果失效。
最终依赖、范围、删除和反馈检查，与当前发布指针切换采用同一事务或等价条件提交。
失败任务保留进度，旧结果只能按其有效状态展示；不能覆盖更新后的资料。

## 考虑过的方案与代价

| 方案 | 未采用的原因或保留的代价 |
| --- | --- |
| 全库放入长上下文 | 不满足用户的按需读取约束，也不能提供明确的范围与处理覆盖 |
| 只用语义搜索或摘要树 | 有利于找候选，但可能漏掉未分类记录、反例及完整统计分母 |
| 只用提示词或文档要求逐层读取 | 可以说明约定，无法阻止模型或宿主工具绕过预算及范围 |
| 执行层受控取证 | 采用；需要维护任务、快照、分页、覆盖台账和失效传播，分析也可能更慢 |

通过 App 检索接口访问的 AI 受到执行约束；纯文件外部 AI 只有导航约定。
README 无法阻止外部平台一次装入整包，不能将文档说明称为技术强制。
无读取工具的 AI 只能接收有限任务证据包，包内必须说明范围、来源与未纳入资料。
该协议保证流程可以核查，不保证每次召回或解释完美；质量仍须通过真实任务评估。
权威资料的保存与导出边界见[ADR 0001](0001-local-source-of-truth.md)。
