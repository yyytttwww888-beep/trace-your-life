# ADR 0001：以本地结构化资料与受管附件作为唯一权威资料

Trace Life 需要长期保存可追溯的个人资料，同时允许其他 AI 按需阅读和迁移。
当前文档基线选择 SQLite 结构化主存与受管附件，统一生成 Markdown 和索引视图。
这个选择以修订、关联和恢复的一致性，换取额外的导出及数据库迁移维护工作。

本决定已纳入项目文档基线，应用尚未实现。
它不表示已选定或验证应用框架、数据库访问库、模型供应商及其他 SDK。
详细数据规则见[主设计](../superpowers/specs/2026-10-16-personal-knowledge-and-reflection-design.md)。

## 决定及边界

- SQLite 保存记录、观察、知识条目、已保存分析、模板版本、用户反馈与证据关系。
- 照片等原始附件保存在应用私有的持久目录，使用稳定 ID 与数据库关联。
- 数据库与附件共同构成一套权威资料；缓存和生成文档不承担主存职责。
- 资料使用稳定 ID 和修订版本，标题、目录及分类变化不改变身份。
- Markdown、导航索引、检索索引和看板结果都是可重建视图。
- AI 生成的内容与依据先保存为分析修订；重新导出不重新调用模型生成结论。
- 第一版通过 App 修改权威资料，再生成阅读视图；外部编辑 Markdown 不静默回写。
- 个人模板导入与完整备份恢复是明确入口，不等同于任意资料双向同步。

第一版只有一个可修改的主库，不建设多个同时写入的手机、电脑或云端副本。
电脑、NAS 和个人网盘可以保存导出副本；它们不会自动成为新的权威资料。
如果以后需要多端编辑，须另行决定身份、冲突和删除传播机制。

## 本地保存与模型分析

“本地主存”限定资料保存方式，不承诺所有 AI 分析离线完成。
使用云端模型时，任务选中的必要文字、图片或证据仍会发送至模型服务。
模型服务、数据处理位置与保留策略须在选型时核实，不能由本 ADR 推定。
读取范围和请求预算由[ADR 0002](0002-controlled-evidence-retrieval.md)约束。

原始记录先可靠保存，模型或网络失败不影响查看已经保存的资料。
系统自动备份和设备迁移需显式配置，并在目标手机验证；它们不替代应用恢复能力。

## 备份与可迁移性

完整恢复备份与 AI 阅读知识包分别提供，导出清单明确范围、版本及完整性。
完整备份包含结构化资料、受管附件、需保留的修订、模板、分析、关联、反馈和删除记录。
阅读包或任务证据包若不包含完整内容，不能称为完整备份。
完整备份默认加密，恢复口令或独立恢复密钥由用户掌握，不能只依赖旧手机密钥。
模型 API 密钥与登录凭据不随备份导出，新设备需要重新配置。

备份保存到应用私有目录之外，并固定一致的数据库快照及附件清单。
不能直接复制正在写入的数据库文件，就视为完成了数据库与附件的一致备份。
恢复先验证格式、校验值和引用，再整体提交；空存储恢复成功是验收条件。
恢复须应用目标端已知的删除记录，避免重新公开已删除内容。
只有删除前的旧离线副本时，无法推知后来发生的删除；外部副本由用户管理。

## 考虑过的方案与代价

| 方案 | 未采用的原因或保留的代价 |
| --- | --- |
| Markdown 直接作为主存 | 阅读方便，但结构化统计、模板版本和跨文档纠错需要额外维护一致性 |
| 仅保留数据库 | 管理集中，但其他 AI 难以直接理解，阅读与迁移依赖专用工具 |
| 本地与云端同时作为可写主库 | 增加同步冲突与删除传播问题，超出当前单人单主库的需要 |
| 结构化主存与生成视图 | 采用；必须维护数据迁移、导出格式、依赖失效及恢复验证 |

本决定使资料修改具有明确入口，也意味着不能直接编辑生成文件来修改 App 数据。
后续实现必须让数据库保存、附件提交与待处理任务可恢复，并维护导出的一致性。
索引可以重建，已保存的分析内容与用户反馈不能仅靠重新运行模型恢复。
