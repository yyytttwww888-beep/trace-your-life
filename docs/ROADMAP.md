## 当前基线与使用方式

- 当前已有 Android 本地记录、模板、修订、受管附件及备份恢复／知识导出后端；构建、测试和安装见[开发文档](DEVELOPMENT.md)。尚未接通外部数据源。
- 按用户最新要求优先实现功能接口和自动化验证，新增前端统一后置；后端测试通过、已接入页面和真实设备验收分别记录。
- 2026-10-19 用户明确暂缓餐食照片分析；M5A 保留为后续范围，当前先推进画像、分析维护与自动运行，华为接入资格验证可独立进行。
- 已选 Kotlin、系统控件、SQLiteOpenHelper、compile/target API 36、min API 26；用户已指定 DeepSeek，图表库待定。
- 手机具体机型、系统版本与华为个人开发者接入资格尚未验证，不能把官方提供能力等同于本项目已经可用。
- 先完成“记录 → 可恢复保存 → 受控整理 → 查阅与回看”的最小完整链路，再扩展输入来源；各阶段以可演示成果和验收证据结束，不以代码量计进度。
- 第一版范围仍以主设计为准。本路线图细化实施依赖，不增加多用户服务、多个可写主库或自动跨设备同步。

## M0：确定实现基础，前置验证外部条件

交付：记录技术选择及理由、目标设备与系统版本、模型调用位置与所需配置；给出后续阶段的可执行开发与验证方式。

- 选定 Android 实现方案、持久存储与附件组织、后台任务执行和系统文件导出方式。
- 核实系统自动备份与设备迁移策略，明确本地保存与云端模型处理的边界。
- 按[华为接入研究](research/2026-10-16-huawei-health-integration.md)验证个人资格、所需权限及睡眠／运动目标字段；记录实际结果与尚未验证的条件。
- 模型选择可与本地基础及 M3 供应商无关的控制流程并行；在接入真实模型前确定可用接口、调用限制、计量和资料处理方式。

验收：应用基础方案可以支撑目标手机运行、离线保存、备份恢复与受控模型调用；华为条件逐项标明“通过／未通过／待验证”，不能笼统写“已支持”。

## M1：先让每天记录成为可用功能

交付：自由随记、可跳过问题的每日复盘、时间与主题入口，以及可导入的个人复盘模板。

- 保存原文、发生时间、录入时间、稳定 ID、修订与来源；允许补记、未知时间和同条记录关联多个主题。
- 提供内置复盘骨架；支持粘贴文本或 Markdown 导入模板、预览调整与模板版本管理。
- 建立受管附件与权威主存的关联，以及修改、归档、删除的明确行为。
- 记录保存和变更任务登记采用可靠提交，为后续整理和增量更新保留入口。

验收：

- 无网络、模型未配置或调用失败时仍能记录、编辑和查看；保存后关闭应用再打开，资料仍完整。
- 同一记录从日期和主题入口定位到同一身份；补记归入正确周期，无法确定时间时保留未知。
- 修改模板后，历史复盘继续显示当时的问题与答案；自由记录不被强制填满结构化问题。
- 修改生成新修订；归档与删除结果不同，删除按主设计处理修订与附件关联。

## M2：先证明资料能恢复，再扩大积累

交付：保存到用户指定位置的完整恢复备份、分层 AI 阅读知识包，以及指定范围证据包；明确各类文件的用途与完整性。

- 固定导出快照和附件清单，保存格式版本、范围、校验信息与相对链接。
- 完整备份包含恢复所需资料、附件、模板、修订与引用；后续新增分析、反馈等类型同时扩展恢复格式。
- 加密备份可凭用户掌握的恢复信息在新设备解密；模型密钥与登录凭据重新配置。
- 提供入口、主题／时间目录、分页证据索引和稳定 ID 定位，原始正文只维护一份。

验收：

- 在空存储中恢复备份，对照原记录、修订、模板、附件和引用；损坏或不完整备份不留下半套可用数据。
- 备份保存于应用私有目录之外，卸载前已导出的文件可用于重新安装后的恢复。
- 文件读取者可以沿索引定位指定事件；有限证据包显式标注范围，不被识别为完整备份。
- 导出中途发生删除时重建或中止；恢复旧备份时合并目标端已知删除记录。

## M3：建立受控 AI 整理与检索

交付：从记录提取观察与知识、按任务查阅依据、形成可核对分析，并完成修正后的可靠更新。

当前完成[受控分析](plans/2026-10-16-controlled-analysis.md)、[模型接入／自动分批](plans/2026-10-17-deepseek-analysis.md)、[核对／反馈](plans/2026-10-17-evidence-review-and-feedback.md)、[正式知识／记录指标](plans/2026-10-17-knowledge-publication.md)、[自动整理／周期材料](plans/2026-10-17-period-reflection.md)、[有界综合／行动实验](plans/2026-10-17-synthesis-actions.md)、[分层周期草稿](plans/2026-10-19-period-reduction.md)及[周期原文核对与发布](plans/2026-10-19-period-review-publication.md)。以下是完整 M3 的验收目标，不能由合成模型替身、少量真实调用或引用结构校验替代。

- 实现协议中的计划、快照、分层路由、分页读取、指标计算、提案及发布职责。
- 执行层限制每次模型输入与取证范围；建立资料、片段和附件处理台账，明确缺口。
- 全周期任务枚举完整目标集合；摘要用于导航，中间成果与最终结论保留原始证据路径。
- 实现任务恢复、幂等重试、范围及依赖失效，以及带并发条件校验的发布。

验收：

- 使用超过单次上下文预算的资料完成分批任务；不能绕过接口一次读取全库，未读附件和片段不被标为已处理。
- 每条新结论能定位实际提供的原文或计算依据；“引用存在但不支持结论”的案例能够被检查或进入复核。
- 未分类记录、补记与时间修订正确影响范围；缺失不补零，摘要重复不增加独立事件数。
- 生成期间纠错、删除或用户否定后，旧任务不能发布为当前；崩溃重启及重复执行不丢任务、不新增重复结果。
- 没有新记录但跨日、过期或时区变化时，相关当前视图仍按协议更新；生成失败不覆盖完整发布。

## M4：形成看板、复盘和长期画像闭环

交付：默认少量关键趋势、日／周／事件复盘、行动回看，以及分维度的当前画像与历史变化。

当前完成看板数据与行动回看视图的[第一阶段后端](DASHBOARD.md)，画像采用、历史、证据定位和迁移的[第二阶段后端](PERSONAL_PROFILE.md)，按目标维度分批生成、核对并明确保存候选的[第三阶段后端](PROFILE_CANDIDATES.md)，以及历史关联、反馈约束、反例扫描和明确更新的[第四阶段后端](PROFILE_MAINTENANCE.md)。[第五阶段](plans/2026-10-19-backend-completion.md)增加纵向长期候选、画像变化摘要、后台记录增量整理、行动进入周期综合及关注项偏好保存。图表页面与健康数值仍未完成。以下为完整 M4 的目标与验收要求。

- 共用指标口径、样本和证据关系，支持 7／30／90 天查看与图表下钻；没有接通的来源显示真实状态。
- 复盘连接期望、实际、解释、经验与行动实验，并在后续周期回看用户选定的行动。
- 按画像设计组织八个维度，区分长期倾向、情境模式和近期状态，保留支持、反例与用户反馈。
- 将新增分析、画像及反馈纳入 M2 的备份恢复与知识包，指标与报告导出保留口径和覆盖。

验收：

- 同一范围内看板与复盘的数字、口径和覆盖一致；只有 4 晚数据时不能生成完整一周的睡眠改善判断。
- 从趋势、复盘或画像中的判断逐层定位到原文；同一共享陈述被修正后，各当前入口一起更新。
- 周复盘能查看先前行动的执行与结果；资料不足时允许保持未知，不用笔记数量生成成长分。
- 用户限定或否定画像解释后不被重复恢复；宽泛身份解释未核对时留在候选范围，近期状态不自动升级为人格。
- 完整备份恢复后，当前与历史画像、模板、行动及证据关联均可核对；长期内容多少取决于真实资料覆盖。

## M5：独立接入照片与健康数据

M5A 当前暂缓，以下保留后续验收范围：餐食拍照、识别结果和少量确认，再依据明确版本的指南分析；遵循[饮食研究](research/2026-10-16-dietary-photo-analysis.md)记录估计、未知和覆盖。

- 验收：重复照片不重复计餐；只拍两餐时只描述这两餐；识别可纠正，照片不明的信息不补成确定分量或全天营养达标率。
- 验收：照片读取失败保留原始记录与待处理状态；模型更换后，已保存识别、分析及其依据仍可追溯。

M5B 在资格与权限验证通过后实现华为数据接入，按实际批准范围读取并记录来源；字段不可取得时如实展示。

- 验收：目标手机完成授权与真实读取；权限撤回、同步失败、记录修订、重复读取均有确定结果，不重复统计。
- 验收：设备观察与同日主观感受并存；同步修订正确更新指标、复盘和画像，来源变化不静默合并为同一口径。

完成前：以个人真实使用链路验证“记录／拍照／已验证健康输入 → 整理 → 看板与复盘 → 行动 → 下期回看 → 备份恢复”；任何未通过阶段均保留明确状态，不能仅凭界面可用宣称第一版全部完成。
