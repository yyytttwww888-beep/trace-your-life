# M3 第四阶段：正式知识、分层阅读与记录指标

用户已要求继续后端开发。本阶段承接[证据核对](2026-10-17-evidence-review-and-feedback.md)，实现[检索协议](../superpowers/specs/2026-10-16-knowledge-routing-and-reliability-design.md)中的条件发布与可追溯读取；前端、周期报告、画像与外部来源继续后置。

## 选择与范围

采用独立保存的不可变知识修订及当前指针。仅给分析任务增加“已发布”标记虽然简单，但正文和依据会受临时任务保留方式影响；直接生成 Markdown 则无法可靠处理并发纠正与恢复。因此 SQLite 保存经过核对的陈述、审核副本及来源，导出按已保存内容生成，不重新调用模型。

条目身份绑定任务和具体陈述，修订记录选定核对、分类、主题和发布时间。分类为观察、知识条目、洞察；分类不改变原陈述的来源性质。概念或方法被保存不代表用户已经掌握。当前不合并跨任务的同义条目，不自动生成长期身份判断。

发布只接受当前来源、未到期任务中得到 `SUPPORTED` 的原陈述。纠正、否定、撤回及永久删除反馈阻止原文发布，不能把用户改写替换进去后沿用原核对。可能解释类内容本阶段还要求用户确认。最终来源、任务版本、核对调用、反馈版本与当前发布版本在同一事务检查；任何竞争失败都不覆盖新状态。同一内容的显式重试不新增重复修订。

正式内容保留本次原文片段、支持引用、问题范围和未知项，不能宣称完整周期已处理或自动穷尽反例。它不是新的原始证据，产品 AI 仍从原始记录接口重新取证；本轮不新增直接向模型开放知识正文的工具。

## 保存与维护

来源修订保守地使旧条目失效，历史可按状态查看；来源永久删除清理机器派生正文，用户独立文字仍依既有反馈规则保留。反馈变化使对应知识失效，永久删除反馈清理其影响的知识历史。任务永久删除同步清理其派生知识。知识删除保留永久标记，旧备份不能恢复该身份。

数据库升级至 v5，逻辑备份至 v4，并兼容旧格式。恢复合并删除台账并保留目标库同身份的知识版本；目标内容的原始证据无法随替换保留时，明确清理并保留删除状态，不恢复备份中的旧版本。恢复后的来源版本推进，历史知识不能因代数碰撞重新变成当前有效。保存和解析均执行数量、字节和引用限制。

## 阅读索引与指标

知识阅读包新增独立知识入口、主题／时间分页、精确 ID 路由和唯一正文。正文关联原始记录修订与片段；所有必要原文均在所选包内才纳入，缺失、过期或范围外条目明确省略。证据包继续只包含原始证据。导出明确表示固定采集时刻的有效快照，离线文件不会随时间或 App 修改自动更新。

应用提供分页知识目录和按 ID 读取接口，分别返回证据状态与用户决定。目录用于定位，知识正文不能经原始证据接口成为自我证明。新增确定性记录指标只计算当前记录数、精确日期记录数、区间与未知日期资料、有记录的天数及每日记录数量；不从自由文字猜测运动分钟、睡眠时长或成长分。多日区间不展开成每天发生，零条记录不表示零活动。统计固定范围和来源版本，可分页下钻；本轮尚不把指标提供给模型。

## 验收

1. 未核对、不支持、已纠正／否定／撤回、删除反馈或未确认的解释不能发布；有效发布幂等，版本竞争不能覆盖。
2. 发布后追加无关分析调用不改变已保存正文；来源、反馈、有效期变化能使当前读取失效。
3. 来源、反馈、任务及知识永久删除传播到所有派生文字；用户独立输入不丢失。
4. 新旧备份格式、引用校验、容量、恢复本地优先及删除优先通过行为测试。
5. 知识导出沿分页主题／时间／ID 定位同一正文，所有证据链接可用，选定范围不扩大。
6. 指标枚举全部目标记录，修订不重复计数，未知和区间时间不冒充单日记录；中途修改拒绝混合版本结果。
7. 运行相关离线测试、lint、APK 构建与 GitHub CI。本轮无模型适配或提示词改动，不重复付费调用来证明纯存储和计算行为。
