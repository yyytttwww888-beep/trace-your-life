# M2：备份恢复与分层知识导出实施计划

按已确认的主设计与用户“先功能、后前端”的要求，实现可独立调用和测试的数据转移模块。本轮不添加页面或文件选择按钮；已有 M1 记录入口继续用于前一阶段验证。

## 模块与接口

- `LifeRepository` 提供完整逻辑快照、受版本检查的文件发布及恢复事务；来源库身份和单调递增的变更代数用于阻止过期结果发布。
- `BackupArchive` 负责可移植的口令加密、版本化结构数据、附件清单、校验及有界解包。恢复不依赖原手机的设备密钥。
- `KnowledgeArchive` 生成只读 Markdown／JSONL ZIP：入口、主题、时间范围、分页证据、ID 分片及唯一的记录正文。指定问题的证据包使用相同路由，保留范围与缺口。
- `DataTransfer` 串接快照、私有工作目录、文件生成、发布检查和恢复。调用者提供目标文件；未来前端通过系统文档服务接入，不把页面状态放进数据模块。

采用逻辑快照而非直接复制正在写入的 SQLite 文件，便于显式校验记录、模板与引用。代价是维护导出结构及其版本，并对总量设置明确上限；超限完整失败，不生成被截断却声称完整的包。

## 一致性与恢复语义

1. 在一致的数据库事务内读取全部保留修订、模板版本、删除记录与变更任务，复制已保存修订引用的附件并核对内容。未提交编辑器草稿不属于完整备份范围。
2. 在私有工作目录构建；最终文件与目标路径位于同一文件系统，发布前再次检查来源库身份和变更代数。来源在导出中变化时中止，后续可重新导出；最终文件不出现半份内容。
3. 备份解密和格式、大小、校验值、引用验证全部通过后才允许修改主存。附件先完整暂存，数据库整套替换采用事务，失败不清除旧的有效文件。
4. 默认恢复只接受空资料库；替换已有资料必须显式指定，并提供预览时取得的目标变更代数。新安装已经初始化内置模板时也属于非空资料库，未来恢复入口须清楚展示替换操作。
5. 恢复保留目标库身份，合并目标端已知删除标记；记录和模板不能因旧备份重新出现。删除模板与待恢复记录的引用冲突时拒绝恢复，不伪造或丢弃用户答案。
6. 当前完整备份覆盖 M1 权威资料。以后新增观察、分析、反馈等持久类型时必须同步扩展版本和恢复验证；模型凭据始终不导出。

## 阅读包约定

阅读包仅包含所选范围的当前记录和必要模板版本，明确 `restorable=false`；历史修订与删除台账由完整备份保留。归档默认包含，未知时间单列。跨期区间单列并给出范围，不把不确定发生时间展开成每天都发生。

索引分页包括主题目录、期间目录和 ID 映射；索引只保存定位信息。完整结构化数据和文件校验清单使用独立文件，不能成为 README 的默认模型上下文。正文只存一次，日期与主题入口均引用它。外部纯文件阅读约定不能替代后续 M3 的执行层读取预算。

## 验收

- 从包含历史修订、旧模板回答、归档、多主题、未知时间和共享附件的合成资料导出，再向空库恢复，逐项核对。
- 错误口令、损坏或截断文件、未知版本、重复条目、路径越界、超限资料和无效引用均失败，原数据库与有效附件不变。
- 恢复旧备份时，目标已删除记录不复活；预览后发生新写入时拒绝覆盖。
- 导出期间发生新增、修订或删除时，旧快照不能发布；失败与中断临时文件可回收。
- 从主题、月份、日／周与 ID 分片沿相对链接找到同一份正文；分页完整且未知／未纳入／附件缺失范围如实呈现。
- 全量运行相关行为测试、Android lint 与 APK 构建；本轮验证后端能力，不把尚未接入页面或真机验证的功能称为已可点击使用。
