# M3 第七阶段：分层周期草稿

依据已确认的[检索与可靠性协议](../superpowers/specs/2026-10-16-knowledge-routing-and-reliability-design.md)，继续完成原文分批综合之后的跨批归并。沿用用户要求：先实现后端和验证，前端后置。

## 设计与取舍

在同一任务、来源快照和范围内，把成功综合批次组织成有向无环依赖图。归并使用独立 `REDUCTION` 调用目的，每次只提供 2–4 个子批次的有来源成果与未知项，逐层形成周期草稿。所有成功原文批次均进入叶清单，包括没有陈述的批次；程序比较最终根与完整叶清单，不能由模型宣称覆盖完成。

直接拼接所有批次会失去请求上限；把摘要当普通原文会混淆证据性质。本阶段采用单独的派生输入和输出类型，沿用既有预算、调用台账及供应商传输，不把祖先原文登记为本次读取。原文仍可沿来源链定位。草稿不是正式洞察，不进入普通陈述发布或自动整理流程；完整原文的语义核对与正式发布另行实现，不能用多个局部支持判断替代整体核对。

输入固定子调用身份、完整输出摘要及相关反馈版本，只允许引用同任务此前的成功节点。所有父输入都是依赖，即使最终陈述没有选它为引用。父反馈变化阻止复用旧节点；否定、纠正、撤回和删除不被静默跳过。永久删除反馈会清理受影响的后代模型文字，保留已消费预算和用户独立内容。恢复先合并删除信息，再清理后代；旧副本不能恢复已知应删除的文字。

编排按稳定顺序分层归并，单独剩余节点向上携带，每轮默认最多 3 次请求。预算不足先减少子节点，两个仍装不下就停止；不得截断或自动扩大任务预算。失败停止本轮，显式继续才重试，在途调用沿用显式恢复。读取进度不调用模型；来源、任务期限和版本变化均返回明确状态。

任务内部载荷升级到 v5，保留旧版本读取。没有新增数据库表或外层备份字段，数据库仍为 v6、完整备份仍为 v5。普通阅读包、原文证据包和已有周期材料包继续明确其范围，不悄悄混入待核对草稿。

## 实施与验收

1. 增加派生输入、依赖图、受控归并执行、严格载荷校验及当前节点读取。
2. 增加可恢复分层处理器、独立覆盖状态和原文下钻入口。
3. 验证备份往返、反馈删除后的传递清理、来源变化与恢复合并。
4. 使用超过 20 个合成批次验证多层、续跑、尾批和空输出；验证单请求始终有界、引用不可伪造、缺父和循环拒绝。
5. 验证新模型提示词的真实 DeepSeek 合成小样本；普通测试和 CI 不读取密钥、不付费调用。
6. 运行相关测试、全量离线测试、lint 和 APK 构建；更新权威接口和实现状态，提交堆叠草稿 PR，不合并。

## 尚不覆盖

分层草稿能比较已保存的局部判断，但可能继承或遗漏模型的解释错误。完整原文语义核对、类型化模型指标、自动反例检索、跨任务同义反馈、后台定时更新及前端仍须后续实现。草稿不能证明生活记录完整，也不生成成长或人格评分。

## 实际验证

2026-10-19 完成独立归并协议、同任务依赖图、可恢复多层处理器、草稿正文与原文下钻、备份和删除传播。新增 43 项离线测试：执行协议 11、分层处理器 18、恢复与导出 8、草稿读取 4、DeepSeek 提示词路由 2；另增 1 项默认跳过的真实归并测试。

全量 406 项中 402 项通过、4 项真实 API 测试默认跳过；lint 无错误、2 项既有依赖升级提示，调试 APK 构建成功。21 个合成叶批次覆盖多轮与重启续跑；反馈在派发前、调用中和成功后变化，分别阻止错误执行、写回及复用。旧备份不能恢复已知应清理的派生文字。

真实 DeepSeek 测试单独通过，1 项成功、0 失败、0 跳过，共 2 次付费请求，无重试。5 个测试构造的局部草稿经两层归并形成 2 条周期草稿陈述；根包含全部 5 个叶节点及去重原文引用，仍不可作为正式知识发布。实际用量为第一层 2,247 输入／637 输出 token、第二层 2,061 输入／518 输出 token。局部提案由合成测试供应商生成，真实模型只执行归并；本次不代表原文提取质量、反例保留率、草稿语义正确率或实体手机验收。

专用草稿文件导出、整体原文语义核对和发布、草稿直接反馈及前端仍未实现；当前正文通过受控后端接口读取，完整备份保留依赖图。接口边界见[周期草稿文档](../PERIOD_REDUCTION.md)。
