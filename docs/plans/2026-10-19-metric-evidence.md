# M3 第九阶段：模型可引用的程序指标

承接用户要求继续完成后端功能，以及上一阶段明确的下一步：让 AI 受控引用程序计算的指标。沿用[检索协议](../superpowers/specs/2026-10-16-knowledge-routing-and-reliability-design.md)，本轮只使用已实现的 `record-coverage` v1，不新增健康数值或页面。

## 实现选择

采用独立 `METRIC_ANALYSIS` 调用，输入固定任务范围内由程序计算的一个类型化指标凭据。原文凭据不变；不把聚合结果伪装成原文，也不混入尚只支持原文的周期归并图。模型输出可能解释，沿既有反馈、独立核对和确认洞察发布流程保存。相比修改所有综合调用，这条独立路径便于核查数值来源及隔离覆盖含义；后续需要混合分析时再扩展协议。

凭据保存完整范围、来源版本、口径、确定性数值、每日序列和完整候选记录 ID／修订清单。清单保存在台账中，模型只收到口径、数值及清单摘要，不能声称读过原文。空期间同样可计算，但零记录不表示零活动。清单最多 10,000 项，仍受既有载荷、字节和请求预算；超限明确拒绝，不抽样或截断。指标身份不含当前计算时间，调用时间由已有台账保存，重试保持幂等。

核对自动重新计算同范围指标并检查凭据一致，调用方不能挑选部分来源或替换计数。所有提案只引用本次指标 ID，类型只能为可能解释；最新核对支持且用户确认后才发布洞察。自然语言中的数字和含义还需语义核对，程序统计正确不代表模型解释必然正确。

## 保存、恢复与导出

分析载荷升级 v7，知识载荷升级 v3，保留旧版读取；SQLite 和外层备份不变。发布在来源与任务版本条件下校验当前完整查询和指标值。来源、反馈、期限、删除与恢复沿用现有失效规则；保留用户独立文字。

备份按实际保存的来源修订重算清单内数值，拒绝缺源、重复、越界及算术篡改。当前数据库不能根据历史代数重建当时所有查询成员；历史清单的自洽性不是历史完整性的认证。恢复推进来源代数，历史凭据保持失效，重新使用必须计算当前范围。

阅读包与周期材料只有在完整包含指标期间及所有来源修订时才纳入对应知识，空清单也检查期间。指标结果、定义和来源下钻独立输出，不经过原文片段读取接口。原文证据包继续保持其既定含义。

## 验收

- 全范围、空范围、未知与跨期日期、归档及精确 ID 的值和来源清单一致；修改、缺失、重复、伪造值被拒绝。
- 模型只收到受预算的指标数据；非法 ID、错误陈述类型、供应商追加输入超预算和载荷超限拒绝；重试、失败恢复、来源／反馈竞争可验证。
- 指标核对重算、确认、发布、失效、反馈删除、旧备份恢复和完整范围导出贯通；旧原文与归并协议不变。
- 运行离线行为测试、lint、APK 构建；使用合成资料显式执行有上限的 DeepSeek 指标解释与核对测试；创建草稿 PR 并核验 CI。

## 验证记录

2026-10-19：完整离线验证共 511 项，505 项通过、0 失败、6 项真实 API 测试默认跳过。新增 46 项离线测试（运行时 15、知识 11、转移 9、指标协议 9、供应商 2）及 1 项显式真实测试。lint 无错误、2 项既有依赖升级提示；调试 APK 构建成功。

显式执行 `DeepSeekMetricLiveTest`：1 项通过、0 失败、0 跳过，最多两次请求且实际执行两次，无重试。合成资料包含 4 条记录，其中 3 条精确日期覆盖 2 天、1 条日期未知；模型准确表达这些数量和 7 天期间，并保留记录覆盖不代表活动、成长或健康的限制。第一次解释实际用量 1,123 输入／275 输出 token，重新计算后的独立核对为 1,439 输入／136 输出 token，返回支持；测试模拟明确用户确认后通过生产事务发布 1 条洞察。没有提供原文或真实个人资料，不代表总体数值解释准确率。

代码复核同时修复普通指标查询可被调用方修改 ID 集合后改变下钻范围的问题，并加入集合变更回归测试。完整范围校验区分同源快照与历史来源，测试包含重新计算哈希后的自洽伪造，避免仅靠哈希存在误认来源完整。

实体手机、新页面、健康指标与原文混合综合仍不属于本阶段。
