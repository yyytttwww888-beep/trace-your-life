# 受控分析接口

本模块已经实现文字取证、请求预算、可恢复调用台账和待核对提案保存；后续已增加 [DeepSeek 适配器及自动分批处理](DEEPSEEK.md)、[陈述语义核对与用户反馈](CLAIM_REVIEW.md)。正式知识通过[独立条件发布接口](KNOWLEDGE.md)保存；可继续[自动整理与查阅周期材料](PERIOD_REFLECTION.md)，或执行[有界原文综合](SYNTHESIS_ACTIONS.md)。跨批归并见[分层周期草稿](PERIOD_REDUCTION.md)；归并陈述可继续通过[周期原文核对与发布](PERIOD_REVIEW.md)，新的[画像候选](PROFILE_CANDIDATES.md)复用原文综合与独立核对，普通入口生成近期／情境提案，[纵向入口](LONGITUDINAL_PROFILE.md)生成需维护核对的长期候选。[行动周期分析](ACTION_PERIOD_REFLECTION.md)另登记行动证据类型。依据是[检索与可靠性协议](superpowers/specs/2026-10-16-knowledge-routing-and-reliability-design.md)，最初实施范围见[M3 第一阶段计划](plans/2026-10-16-controlled-analysis.md)。

## 调用入口

在后台线程使用 `TraceLifeApplication.analysis`，或构造 `ControlledAnalysis(repository, clock)`。提取经 `runBatch`，核对经 `reviewClaim`，均由 `ControlledAnalysis` 统一执行预算与台账；`LifeRepository`、备份快照、任意文件读取均不向模型开放。

```kotlin
val request = AnalysisRequest(
    question = "这一周记录了哪些进展和问题？",
    scope = AnalysisQuery(
        from = LocalDate.parse("2026-10-12"),
        through = LocalDate.parse("2026-10-18"),
        zoneId = "Asia/Shanghai",
    ),
    expiresAt = Instant.parse("2026-10-19T00:00:00Z"),
)
val task = analysis.start(request)
val route = analysis.route(task.stored.id)
val page = analysis.evidencePage(task.stored.id)
val fields = analysis.fields(task.stored.id, page.page.items.first().id)
// 配置 DeepSeek KEY 后可调用 runBatch，或由 AnalysisBatchProcessor 自动选择下一批。
```

| 接口 | 返回与约束 |
| --- | --- |
| `start(request, id)` | 固定范围、源库身份及来源代数；同 ID 同计划幂等，不同计划拒绝 |
| `route(id)` | L0 任务入口、L1 关注主题、L2 范围计数和下一页大小；不含原文 |
| `evidencePage(id, offset)` | L3 有限元数据页；日期、版本、主题和时间归属，不含正文与答案 |
| `fields(id, recordId)` | L4 字段入口、码点长度与附件缺口；精确 ID 同样验证范围 |
| `runBatch(id, batchKey, selections, provider, instructions, history)` | 构建完整请求、检查预算、登记尝试、执行适配器、校验并保存提案 |
| `navigate(id, provider, selections, batchKey)` | 在内容调用前进行一次有预算的语义导航；登记问题或显式原文，返回主题与本地查找词，不产生知识陈述 |
| `claimRef` / `reviewClaim` / `currentReview` | 绑定提取陈述、重新取证核对、读取与当前反馈版本匹配的意见；详见核对接口 |
| `coveragePage(id, offset)` | 分页返回文字处理覆盖、未处理附件及不可读取资料；不代表生活记录完整 |
| `task(id)` / `tasks(offset, limit)` | 查看任务、状态、调用、证据和历史提案；过期或失效状态明确显示 |
| `recoverInterrupted(id)` | 工作者重启后，把遗留在途调用转为可重试；不自动重复派发 |
| `delete(id, expectedVersion)` | 按版本删除任务与提案；保存删除标记，旧的受管备份不能恢复该任务 |

可空的 `AnalysisRequest.profileTarget` 固定画像维度与近期／情境层次；此类任务允许 `SYNTHESIS`、`REVIEW` 及维护专用 `PROFILE_RELATION`／`PROFILE_SCAN`，详见[画像候选](PROFILE_CANDIDATES.md)和[跨任务维护](PROFILE_MAINTENANCE.md)。维护计划只保存目录身份与摘要，模型比较按需读取单条参照；最终核对受完整扫描和当前历史依赖约束。普通任务保持原有行为。

计划日期均为包含端点的绝对发生日期，不用录入时间替代。完整周期的主题仅为关注提示，不排除误分类和未分类记录。`recordIds = null` 表示全部；非空 ID 集合是用户明确指定的子范围，缺失、归档排除或不在期间的 ID 由 `missingExactIds` 报告，空集合拒绝。

范围内全部区间归为 `WITHIN`，只部分重叠归为 `OVERLAP`，未填日期归为 `UNKNOWN`。后两者是候选及缺口，不能擅自计为确定发生在这个周期。记录保留其原时区，计划另有适用时区；日期粒度记录不虚构时刻或做跨时区瞬时换算。

## 片段与逐次证据登记

文字入口是 `body` 与 `answer:<questionId>`，附件入口为 `attachment:<id>`。片段范围采用 Unicode 码点，左闭右开；原文不做 trim 或归一化。SQLite 直接截取指定字段片段，避免为了读一段加载整条长记录。复盘答案携带所绑定模板版本的问题和提示，其大小同样计入输入。

每次调用保存记录 ID、修订、字段、起止位置、字段总长度、原文 SHA-256 和完整请求摘要。原文片段本身不再复制进任务表；问题、模型候选文字及未知项属于任务内容，纳入删除与备份管理。引用只能使用本次提供的证据 ID；过去其他批次读过的片段不能自动成为本次结论的依据。

只有通过结构、引用及输出大小校验的成功提取调用，其输入片段才计入“成功调用处理覆盖”。核对调用的额外上下文不增加提取覆盖。重叠片段合并计算，不重复计数；失败、在途、中断调用均不算完成。空提案也是合法输出，但不说明没有问题。覆盖完整不证明理解完整，更不代表该周所有生活事项都被记录。

附件当前不会提供给模型，始终保留独立缺口。含 NUL 的文字无法用 SQLite 文本函数安全分片，明确报告不可读取，原始记录仍保留。未读尾部、其他答案和附件不会因为记录的一个片段被读取而消失。

原文综合及单条语义核对的请求另外携带本次输入的精确 `coverage`。程序仅分页读取固定来源的字段类型、长度及附件目录，合并本次回执的 Unicode 区间，分别计算 `providedFieldsComplete`（本次涉及的每个字段都完整）、`providedRecordsTextComplete`（本次涉及的记录全部文字字段都提供）、`allScopeTextProvided`（固定范围全部文字均提供且无缺失指定身份或不可读记录）。这些值只针对当前请求，不累计其他批次曾经读过的文字，不额外读取正文或把字数转成个人事实。

`scopeAttachments` 为范围内附件数量，`attachmentsRead=0` 明示当前未读取附件；范围确实没有附件时数量为 0，不虚构附件缺口。若不可读记录导致该记录的字段与附件目录无法安全取得，附件总数为 `null`，`unreadableRecords` 明示数量，不把未知说成零。`semanticallyVerified=false` 只表示这些程序覆盖值不证明语义成立；不能将尚未核对理解成文本尚未提供。完整文本仍可能记述不完整的生活，语义核对也不能据此断言未知事实或穷尽现实中的反例。

## 预算与适配器契约

默认每页 25 条，每片段 1,024 码点；每批 1–32 个片段。完整请求包括系统指令、额外指令、历史、范围与计数、模板问题、证据元数据和正文。默认单次输入 64 KiB / 12,000 tokens，输出预留 2,000 tokens；单任务最多 100 次尝试、累计输入 1 MiB，提案输出 32 KiB。具体可配置范围由 `AnalysisLimits` 拒绝越界值，不能省略预算后无限读取。

`AnalysisProvider.prepare` 生成实际发送的完整请求体及计量，执行器对该请求体计算字节预算和摘要；`completePrepared` 只能发送该请求，不能追加隐藏历史、工具或其他资料，并遵守 `maximumOutputTokens`。适配器 `id` 固定供应商、模型、封装及计量版本。计量明确区分 `EXACT` 和 `CONSERVATIVE_UTF8_BOUND`，后者不是实际 token 用量。DeepSeek 使用有公开 tokenizer 依据的保守上界，响应实际用量另行校验和保存，详见[预算与校验](DEEPSEEK.md)。默认接口保留用于合成测试的直接计量行为。

请求超过任一预算时拒绝派发，调用者应减小批次或留下未处理缺口；不会静默截断或扩展范围。异常文本不保存，防止供应商错误串带入完整敏感请求。输出仅允许有限数量的待核对自述或可能解释，每条都有本次引用；它没有直接修改原记录、统计或当前画像的权限。

## 恢复、失效与备份

发送前保存 `IN_FLIGHT`，成功后条件写回 `SUCCEEDED`；失败保存安全原因码。登记后崩溃无法证明外部是否收到请求，恢复为 `INTERRUPTED`，保守计入尝试和输入预算。相同批次只能以相同请求摘要和适配器重试；提供稳定幂等键，但外部服务是否支持幂等去重需适配器另行验证。成功批次重试直接读取已保存提案。

来源写入和分析进度使用不同代数。任务保留创建时的 `SourceStamp`，通过数据库中的 `SourceScopeLedger` 判断之后的变更是否影响固定 `AnalysisQuery`，不会把旧来源戳换成新戳来冒充重新分析。变更台账只保存记录身份、日期区间与归档状态；触发器记录变更前后两侧，日期移出旧范围也会使旧判断失效。范围外且不影响候选集合的新增或修改可以保留任务当前性；落在范围内的补记即使尚未引用仍会使任务失效。同期间主题不同不能视为无关，未知日期、归档条件和显式 `recordIds` 分别按原范围判断。

每次受控读取、派发前及结果写回均检查范围当前性，写回版本检查与保存处于同一事务。来源全库代数仍用于一次读写、分页和导出快照的一致性检查。已经发送给外部服务的请求无法撤回，期间发生相关修改或删除会阻止旧结果写回。schema v9 的迁移和恢复设置来源台账可信下界；早于该边界、缺少可证明变更历史的旧任务保守失效。恢复不会导入台账或自动恢复任务授权，细节见[数据转移](DATA_TRANSFER.md#一致性与中断)。

`expiresAt` 到达后，即使没有新记录，任务仍拒绝新取证、模型执行及当前核对结果读取；历史任务台账仍可查看。固定历史任务可不设置到期时间。已授权的周／月任务会建立各自固定范围的新任务，见[后台分析](BACKGROUND_ANALYSIS.md)；过期或来源变化的历史任务保留待更新状态，不偷换窗口与来源身份，也不能当作永久有效的“近期”分析。

永久删除记录时，程序按已登记的原文回执、完整指标来源清单及知识证据链确定受影响任务和知识，并沿跨任务画像维护依赖继续清理机器文字与历史；失败或在途调用登记的输入也参与判断。同一任务读取过被删除资料时会清理该任务，不承诺逐句保留其余输出。仅范围重叠但未实际读取该记录的任务进入待更新，无关任务与知识保留。已使用的模板禁止删除；删除未使用模板不再清空分析与知识。

独立用户反馈、行动计划与回看、画像用户文字不随机器知识清理；引用状态可能变为失效或缺失。永久删除反馈仍会清理受该反馈影响的核对正文，保留预算台账。规则见[核对与反馈接口](CLAIM_REVIEW.md)。单独删除任务不改变来源代数，其删除标记参与恢复合并；恢复也应用实际取证和跨任务依赖清理，不能重新带回已删除资料的派生文字。

活动任务最多 100 个、合计 16 MiB；已归档任务独立限制 10000 个、合计 64 MiB，单任务载荷 2 MiB。在途任务的最大输出也预留保存容量；完成后可归档收起而保留知识依据，详见[分析归档](TASK_ARCHIVE.md)。完整加密备份保存任务、台账、提案和任务删除标记；恢复后原来源身份和代数仍保留，任务作为失效历史，不自动重跑。阅读包暂不包含分析提案，并在清单注明。格式和并发检查见[数据转移接口](DATA_TRANSFER.md)。

## 后续验收

M3 已实现语义核对、独立纠正、条件发布和记录覆盖指标；后两者见[知识接口](KNOWLEDGE.md)。普通核对只检查明确提供的原文；画像维护已增加固定范围内逐片反例扫描及跨任务关系与反馈约束，范围外资料和语义漏判仍是明确限制。这些处理接口由调用方启动一轮，Android 调度与付费授权通过独立[后台分析](BACKGROUND_ANALYSIS.md)管理。提取和综合输出均保留候选状态，必须经独立发布检查才能进入正式知识；[自动整理器](PERIOD_REFLECTION.md)可串起提取、核对和发布。有界综合的独立输入覆盖与多批未整合状态见[综合接口](SYNTHESIS_ACTIONS.md)。[模型可引用的记录指标](METRIC_ANALYSIS.md)使用独立调用，健康指标和自动更新后置。手机主动入口见[分析与发现](REFLECTION.md)；对话式回看自动纳入范围内的行动计划与回看，快捷周期分析可明确选择行动流程。Robolectric、APK 构建、模拟器和实体手机验证分别报告。

普通主动分析可启用历史意见约束，目录与内容分开读取、实际内容计入完整请求预算；独立意见不作为原始证据，语义对照与原文核对分别保存。当前每次最多参考 8 条，发布前完整目录由用户逐项对照；详见[历史意见](HISTORICAL_FEEDBACK.md)。

## 受控追问背景

[对话式回看](CONVERSATION.md)复用同一执行器。追问背景自载荷 v14 引入，登记上一任务选定陈述、来源、反馈及控制状态；含已有理解的任务使用下节 v15，普通旧任务保留此前兼容形状。模型仅收到最多 6 条派生背景，背景不能充当原始证据，其字节与 token 计入完整请求预算。每次执行、条件保存、知识读取及导出检查祖先依赖，纠正和删除沿引用传播；聊天记录不作为隐藏上下文附加。

## 统一知识问答的依赖

`AnalysisRequest.knowledgeContext` 保存经本地有界目录选出的固定知识、经验与已采用画像版本。它是控制背景，不注册为原始证据；模型返回背景键作为引用时拒绝结果。完整载荷、供应商封装和历史／追问背景共同计量。准备、派发、迟到结果保存、发布、读取和导出均检查固定背景仍然有效。删除背景或其来源会沿依赖闭包清理机器结果，用户独立文字仍按自身规则保留。具体目录边界与页面行为见[对话式回看](CONVERSATION.md)。

经验背景的 `revision` 固定实际采用的 `INITIAL`、`NARROW` 或 `REPLACE` 事件 `sequence`，并核验该事件的知识修订与说明，不使用整条线索的总版本作为内容身份。追加 `SUPPLEMENT`／`EXCEPTION` 不改变当前正文，不会仅因线索版本递增而使已有回答或保存知识失效；收窄、替代及原始资料、知识、反馈依赖变化仍按既有规则传播失效。恢复核验精确历史事件，允许后续出现新的事件，但不把历史背景重新认证为当前。详见[经验线索](EXPERIENCE_CONTINUITY.md)。

含此背景的任务使用 v15；长期画像出现跨批归并时使用 v16，普通旧任务继续保留原版本形状。长期画像归并只接受已完成核对的对应目标批次，完整维护证明携带叶原文及祖先反馈；归并本身不等于可以保存画像，仍须完成全部范围扫描与最终核对。见[纵向画像](LONGITUDINAL_PROFILE.md)。

内部字段盘点按任务配置的页大小集中验证，只返回字段位置／长度与不可读缺口，避免对每条记录重复解码整份任务台账。页面前后检查固定版本、来源、时间及背景，处理候选仍逐次经过受控原文取证；没有跨请求缓存。

## 语义导航与 v17 台账

对话首次处理先执行 `NAVIGATION`：模型只解释已保存的问题，给出有限主题和查找词。程序据此在本地目录分页筛选，保存固定知识背景；不会把整个目录或个人原文一并发给模型。用户主动点“按内容建议主题”时，导航可读取显式登记的记录片段，建议仍需用户选择后才保存为普通记录修订。两种导航共享内容分析的请求次数、输入、输出与任务容量预算。

导航成功后，`AnalysisRunState.knowledgeContext` 指向本次选出的固定背景，原始请求不改写。成功批次重入直接读取台账；内容调用开始后禁止重新导航。失败不会隐藏重试或扩展读取范围。主题与查找词不能充当事实引用，导航没有提案、核对或发布权限。知识选择、内容调用、发布及导出均验证当前有效性，删除与备份恢复会检查初始与导航后全部保留的背景依赖。

含导航回执的任务使用 v17；此前 v1–v16 任务继续兼容原格式。v17 同时校验导航输出大小、上下文形状、调用顺序及证据绑定，存储预留包括完整有界背景。具体页面流程与目录上限见[对话式回看](CONVERSATION.md)与[主题叫法](TOPIC_ALIASES.md)。
