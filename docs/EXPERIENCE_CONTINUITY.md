# 经验线索与跨周期积累

经验线索把不同时间已保存的知识连接为一条可继续积累的理解。它有独立、稳定的身份；原知识的 ID、修订、原文依据与核对结果保持各自的身份。模型不会自动把相似文字合并，关联也不构成新的原始证据。

本轮设计与范围见[持续积累设计](superpowers/specs/2026-10-20-experience-memory-and-archive-design.md)。知识发布与当前性继续遵守[知识接口](KNOWLEDGE.md)，历史纠正如何进入新分析由[主动分析接口](REFLECTION.md)说明。

## 用户选择的形成过程

`StoredExperienceThread` 保存稳定 ID、当前版本、用户填写的名称、主题、创建与更新时间。名称与主题在本轮创建时明确保存；后续关联不会自动改写它们。

`StoredExperienceChange` 保存同一线索中的顺序号、固定 `knowledgeId`／`knowledgeRevision`、关系、独立用户说明及加入时间。事件不复制机器生成的正文。每次追加事件使线索版本递增，原事件不改写。

| 关系 | 阅读含义 | 是否改变目前采用的理解 |
| --- | --- | --- |
| `INITIAL` | 第一条知识作为起点 | 是，仅第一步使用 |
| `SUPPLEMENT` | 补充另一段经历或理解 | 否 |
| `EXCEPTION` | 由用户标记一个例外 | 否，须写明原因 |
| `NARROW` | 用新知识限定适用条件 | 是，须写明原因 |
| `REPLACE` | 用新知识替代原来的理解 | 是，须写明原因 |

“目前采用的理解”定位最近一次 `INITIAL`、`NARROW` 或 `REPLACE` 事件。采用表示用户的组织选择，不代表证据永远有效。若它的知识过期、被纠正、原文变化或被删除，页面显示实际状态，不自动把更早的解释恢复为当前结论。补充与例外始终可在形成过程中定位。

## 接口与分页

以下为受信任的应用接口，在后台线程使用；不是模型可以任意读取全库的工具。

```kotlin
val continuity = KnowledgeContinuity(repository)
val thread = continuity.create(
    knowledgeId = saved.id,
    revision = saved.revision,
    title = "开始复杂任务前的准备",
    topics = saved.topics,
    userNote = "我想持续观察任务复杂度的影响",
    id = stableUserOperationId,
)
val updated = continuity.append(
    id = thread.id,
    expectedVersion = thread.version,
    knowledgeId = nextWeek.id,
    revision = nextWeek.revision,
    relation = ExperienceRelation.NARROW,
    userNote = "简单练习可以直接试，复杂任务应先确认接口",
)
val topic = continuity.page(topic = "学习", limit = 20)
val related = continuity.page(knowledgeId = saved.id)
val detail = continuity.get(thread.id, limit = 20)
```

新建和追加都在 SQLite 事务中再次检查所选知识的固定版本：必须仍为当前修订、依据当前有效，并且发布时间没有晚于本次读取时刻。不能用历史页面的旧版本或待更新结论建立新关联。同一知识修订不能重复加入同一线索，但可以明确加入不同线索。

`expectedVersion` 防止旧页面覆盖后来发生的变化。创建允许调用方传稳定操作 ID；内容一致的创建重试返回原线索，不能复用该 ID 绑定不同内容。手机表单保存该 ID，避免旋转或重试制造重复线索。

目录可按主题或知识身份筛选；每页最多 100 条。详情按最近一次变化向前分页；目前采用的理解独立定位，不依赖它是否落在本页历史中。翻页传入上一页的 `previous`，固定来源、分析代数及评估时间；资料变化后须重新读取。读取时重新解析固定知识修订，用户反馈与证据状态分别展示。

## 手机入口

知识库主题区展示已有经验线索；即使相关原文和机器知识被删除，独立经验说明的主题仍可找到。从知识详情可进入已有线索，或点击“建立或加入经验线索”选择新的积累位置。

创建时由用户填写名称和可选说明；加入已有线索时展示原来的理解，并要求选择补充、例外、收窄或替代。手机端支持查看目前采用的理解、逐步形成过程、独立原因及关联知识的固定版本与依据。表单文字和关系选择在页面重建后保留。保存动作不发送模型请求。

本轮尚未自动推荐同义线索、自动归并、重命名主题或修订既有事件关系。关联内容若需要重新分析，仍从已有分析与核对入口产生新的知识，再明确接入这条经验。

## 删除、纠正与备份

机器正文只存在原知识修订中。永久删除来源、反馈或知识时，既有删除依赖继续清理相关机器内容；经验线索没有把该正文复制到别处，所以再次阅读仅显示知识不可用。用户亲自写的名称和事件说明保留。用户对知识的纠正、否定与撤回继续由反馈接口维护；知识仍存在时，经验详情会展示这些独立意见及待更新状态。

`continuity.delete(id, expectedVersion)` 永久删除线索及其全部独立说明，保存删除标记；原有知识、记录、行动不因此删除。手机页面提供明确的删除确认。被永久删除的线索 ID 不可复用。

SQLite v10 增加线索、不可变事件、主题索引及删除台账，更新这些内容会改变分析代数，从而拒绝旧导出和旧恢复预览。完整备份 v9 包含 `experienceThreads`、`experienceChanges`、`deletedExperienceThreads`。恢复验证连续事件链、唯一身份、单线索内固定知识修订不重复、关系约束与时间一致性。知识引用为软引用，可保留来源已不可用的独立用户说明。

恢复时，目标库已有线索的整条事件链优先，不被旧备份回滚；任一侧的永久删除标记优先。恢复不会把引用的旧知识重新认证为当前。线索上限为 10,000 条，事件 100,000 条，删除标记 100,000 个；单项 JSON 最多 16 KiB，线索与事件合计最多 32 MiB，超限整笔拒绝。

## 阅读包

阅读包从经验索引进入单条线索与固定知识链接。范围导出只保留本包已纳入的固定知识修订对应的事件及独立说明；被省略事件的说明不进入包，也不补录缺失的机器正文。完整历史通过完整备份保留。

导出保留原来采用事件的顺序号。若目前采用的理解不在所选范围内，包内明确说明这个缺口，不把较早的包内事件假装成当前理解。关系和用户文字保持其来源性质，不能作为原始证据。导出仍绑定采集时刻与范围，离线包不会在手机后续修改后自动更新。

## 验证边界

`KnowledgeContinuityTest` 覆盖跨周同一身份、补充与例外、来源与反馈变化、删除保留独立说明、并发版本、分页快照、创建重试、加密备份往返、恢复防回滚与删除台账、损坏历史拒绝等场景。`KnowledgeActivityTest` 包含创建线索、表单重建、再次加入同一身份、收窄理解与删除来源后的页面行为。实际运行结果统一记录到[开发与验证](DEVELOPMENT.md)，不以测试代码存在代替测试通过或真机验收。
