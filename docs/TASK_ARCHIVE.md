# 分析任务归档

归档将已结束处理的分析移出活动工作区，同时保留其问题、范围、调用台账、完整核对证明及原文定位。已保存知识继续引用原任务，不因归档而失效。归档不会确认、核对或发布发现，也不会删除历史以腾出空间。

手机「分析历史」提供活动与已归档两种入口；任务详情可明确归档，之后也可恢复为活动任务。归档仅改变处理生命周期，证据是否过期、来源是否变化、用户是否否定继续分别显示。若还有未保存发现，恢复为活动任务后才能继续核对；恢复本身不发起模型请求。

## 应用接口

接口在应用 IO 线程使用，不向模型开放整库任务读取：

```kotlin
val usage = repository.analysisStorageUsage()
val page = repository.analysisRunIndex(
    prefix = "reflection-v1-", archived = true, offset = 0, limit = 25,
)
val archived = repository.archiveAnalysisRun(runId, expectedVersion)
val reopened = repository.unarchiveAnalysisRun(runId, archived.version)

// 手机工作流使用相同存储协议并恢复只读视图。
val history = app.reflectionWorkflow.historyPage(archived = true, offset = 0, limit = 20)
```

`AnalysisRunIndex` 只包含 ID、版本、创建／更新时间、期限及 `archivedAt`。SQL 先按任务前缀与生命周期筛选，再按创建时间和 ID 倒序分页；不会只取最早 100 个任务后在内存过滤。单页 1–100 条，选中具体任务后才读取完整 payload。记录本身的归档与分析任务归档是两种独立操作。

`archiveAnalysisRun` 与 `unarchiveAnalysisRun` 事务内检查调用者实际查看的任务版本，成功改变生命周期时版本递增。任何在途请求都阻止归档；应先等待完成或明确恢复中断。底层允许用户主动封存尚有待处理内容的任务，页面须明确它仍未完成。恢复活动状态重新检查活动容量，不自动调用模型、不退款已消耗额度。

正常的任务保存禁止写入已归档任务，模型调用先持久登记在途状态再发送，因此归档不能留下可继续收费的隐含执行通道。已有成功调用的只读结果、固定证据及来源正文仍可通过原 ID 查阅。用户反馈是独立资料，归档后仍能纠正、否定、撤回和维护自己的说明；反馈变化使关联知识按原协议进入待更新状态。

## 保存与容量

SQLite schema v10 在原分析表增加 `archived_at`，完整 payload 原位保留；没有另建一份可能失去依赖的简化摘要，也没有改写原始来源戳。归档与恢复改变分析代数，使尚未提交的导出和恢复预览失效，但不改变来源代数。v9 升级不会改变此前知识的来源有效性。

| 资源 | 上限 |
| --- | --- |
| 活动任务 | 100 个；payload 与在途响应预留合计 16 MiB |
| 已归档任务 | 10,000 个；payload 合计 64 MiB；不能有在途响应 |
| 单个任务 | payload 与适用预留最多 2 MiB UTF-8 |
| 历史目录 | 单页 1–100 项元数据 |
| 完整备份结构 JSON | 128 MiB，另受领域数量、字节和节点预算约束 |

活动预算保持原值，归档任务不占用它。独立归档容量是明确的本地资源边界，不承诺无限年限；到达容量时操作失败并提示管理历史。不会自动删除任务或正式知识，也不会绕过容量继续在线调用。知识、独立反馈、经验线索及原始记录各自的保存上限仍然适用。

日常目录使用元数据分页，完整任务的最大 2 MiB payload 继续通过有界 SQLite 文本切片读取，避免超过 Android CursorWindow 行限制。备份是受信任的本地全库操作，可读取受整体预算限制的全部任务；这不改变模型必须按范围、分层索引和预算读取的协议。

## 删除、备份与恢复

记录、任务、反馈及跨任务控制背景的永久删除，仍沿真实输入和依赖闭包处理活动及归档任务。归档不豁免删除，不留下第二份已被要求删除的机器正文。用户独立反馈、经验说明和手写对照理由按各自协议保留，不当作原始证据。对照理由单独存储；即使机器任务已被清理，也可从独立说明目录查看或明确永久删除，完整备份保留其版本和删除决定。

逻辑备份 v9 保存 `archivedAt` 与原任务完整 payload，兼容旧版备份；旧版任务默认活动。恢复前分别校验两类预算、任务形状、证据指向、反馈删除和派生依赖。归档任务不能利用备份混入在途调用或被重新标为当前有效来源。知识阅读包仍只包含采集时有效且有完整范围依据的正式知识；任务处于归档状态本身不构成省略理由。

恢复沿用明确的替换语义：分析台账（包括归档任务）由备份恢复，**不会合并仅存在于目标手机的更新分析历史**。恢复较早备份可能回退这些任务；操作前应另存当前完整备份。目标已有用户反馈、经验线索、行动、画像及已知删除标记继续按[数据转移协议](DATA_TRANSFER.md)合并优先；这种保护不等于通用双向同步。恢复后的知识保持原来源身份，可作为历史查阅，需要新任务重新分析当前来源。

## 验证入口

`AnalysisArchiveTest` 使用合成资料覆盖 365 次每日分析加 52 次每周分析、归档后的有效知识、跨页目录、完整加密备份与知识阅读导出、恢复、新旧活动容量隔离、在途调用与旧写回阻断、用户纠正／删除传播，以及 v9 原地迁移。普通验证不调用网络，不读取真实密钥。

```bash
./gradlew testDebugUnitTest --tests 'dev.tracelife.storage.AnalysisArchiveTest'
```

该文件列出行为验收范围；实际运行结果、APK 构建与模拟器检查统一记录在[开发与验证](DEVELOPMENT.md)，不能将测试代码存在当作已经通过或实体手机长期使用验收。

## 手机上的全部任务管理

主动分析首页「更多任务 → 管理全部分析与整理」及整理页「管理分析记录与归档」可按活动／归档状态分页管理所有任务类型，包括后台整理。每次读取当前页；在途任务不可归档。归档和恢复只改本地生命周期，不发起模型请求；判断有效性仍由来源和反馈决定。
