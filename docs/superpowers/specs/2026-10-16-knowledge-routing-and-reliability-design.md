# Trace Life：分层检索与维护可靠性协议

日期：2026-10-16。状态：用户已明确要求的流程约束及拟议实现设计，应用尚未实现。

本协议适用于用户查询、定期复盘、画像更新、餐食解释及其他 AI 分析。它细化[主设计](2026-10-16-personal-knowledge-and-reflection-design.md)，并约束[画像设计](2026-10-16-long-term-personal-profile-design.md)。应用必须经过索引路由和受控取证，不得一次性把全库内容装入模型上下文。

## 1. 必须遵守的约束

1. 先确定任务、范围、来源版本与读取预算，再按索引定位证据。日常后台任务同样执行该协议。
2. 模型通过受控接口读取资料；执行层限制单次返回量与模型请求的总输入量。没有可绕过预算的全库读取接口。
3. 索引负责定位，摘要负责提供概况，原始资料与按明确口径计算的结果负责支撑新判断。已有分析不能自我增信。
4. 全周期统计枚举整个目标数据集合并由程序计算；全周期文字分析分批处理范围内资料。检索命中的前几条不能代表整体。
5. 每项结论关联实际提供给模型的证据及版本，说明范围和缺口。引用存在与语义得到支持分别检查。
6. 模型只能提交分析或变更提案；程序校验通过后才能发布。一般整理可自动发布，宽泛身份解释另按画像核对规则处理。
7. 记录修订、新补记、删除、来源变化及用户反馈必须传播到相关索引和结论。失效内容不能继续充当当前有效判断。
8. 预算耗尽或资料未就绪时保存进度、报告已处理范围，不能偷偷扩大读取，也不能将部分处理声明为全部完成。

这些约束可机械检查流程与一致性；模型对自然语言的理解仍可能出错，需另行评估、核对证据和吸收用户纠正。

## 2. 四层索引与原始证据层

这是逻辑层次，时间、主题、情境和稳定 ID 构成交叉入口，不是互相隔离的文件夹树。已知记录 ID 时，完成入口和范围验证后可以直接定位相应证据；跨领域任务可以沿明确路由跨分支，仍受同一预算和覆盖规则约束。

| 层次 | 保存什么 | 典型入口 | 职责 |
| --- | --- | --- | --- |
| L0 入口索引 | 协议、知识包版本、能力、一级目录和任务路由 | `README.md`、小型 `manifest.json` | 确定任务类型、可用来源和下一步入口，不装载全量目录 |
| L1 领域索引 | 主题、别名、画像维度、指标口径与相关分支 | `topics/index.md`、`profile/index.md`、`timeline/index.md` 等 | 选择问题涉及的领域；需要概览时读取相应短摘要 |
| L2 范围索引 | 时间段、来源类型、情境、数据数量、待整理项、分片位置 | 月份索引、主题的期间入口、受控接口返回的范围清单 | 明确待查集合；保存纳入／排除条件与当前覆盖 |
| L3 证据索引 | 事件 ID、记录及修订 ID、内容类型、时间、片段位置、支持和反例关联 | 分页证据目录、ID 查询入口 | 定位和去重，选择本批要读取的原文与计算结果 |
| L4 原始证据 | 指定记录的字段、片段、完整原文或附件，及可复算的指标结果 | `records/`、受管附件、指标查询结果 | 核对陈述、上下文和数值，支持具体判断 |

应用中的范围和精确 ID 查询由结构化主存完成；导出知识包提供对应的分页文件入口。第一版不预先生成每个主题、时间、情境的全部组合，按固定时间分片及必要范围清单组织，避免索引数量失控。

### 每个索引节点的最小信息

- 节点 ID、修订、所属知识包／来源快照、索引格式版本。
- 节点性质：导航、摘要、证据目录或内容；导航文字不被冒充原始证据。
- 覆盖的时间、主题、来源和状态，记录数、待整理数、无法处理数及已知缺口。
- 下一级入口、相关分支、别名和精确引用；超过分页大小时返回后续游标或分片路径。
- 索引与源数据的同步状态、生成时间、依赖范围版本和已处理到的位置。
- 单页大小提示；标题、别名、简短说明与正文分开，防止索引长期膨胀为全量摘要。

索引内容来自确定的资料清单与受控生成流程。AI 可以建议主题或关联，但不能私自改写正式路由与记录数量。未分类记录必须存在于时间／来源索引和待整理入口。

## 3. 不同任务使用不同取证方式

| 任务 | 路由与取证 | 完成条件与限制 |
| --- | --- | --- |
| 查一条记录、某次决定 | 时间／来源条件、ID、关键词和语义检索组合，回到原文 | 找到具体证据；没有命中只能报告已查范围，不等于不存在 |
| 查看当前概览或画像 | 读取当前有效条目和其范围、来源性质 | 可以复用未过期的既有内容；这是呈现已有判断，不是重新验证画像 |
| 睡眠、运动等趋势 | 固定期间与指标定义，程序对全部合格数值聚合 | 样本、去重、缺失与分母清楚；模型读取结果与必要记录，不必接收全部数值原文 |
| 一周有哪些进展或问题 | 枚举该期间全部记录的元数据，分批读取相关正文、附件提取与确认内容 | 有处理台账；未处理或未解析内容列为缺口。主题标签只影响优先级，不能成为静默排除依据 |
| 探索一个原因或模式 | 从相关领域和时期出发，检查其他情境、反例、替代解释和用户反馈 | 表述限于取证范围；跨分支扩展记录理由；搜索结果不直接构成因果证明 |
| 新增或修改长期画像 | 跨周期、跨情境核对原始事件，检查支持、反例、先前否定和新资料 | 不能只读旧画像或周报再生成更强判断；按照画像层次与核对要求发布 |
| 处理一条新记录 | 新记录及必要模板、指标或指南；需要关联时再请求相应索引范围 | 可以从新事件的精确入口开始，但仍建立范围和证据包；不为了分类加载完整个人历史 |

用户给出的确定日期、来源及精确 ID 可以作为硬范围条件；AI 提取的主题和语义相关性通常只作为候选信号。声称“这个期间全部记录中的情况”时，必须处理其完整集合，包括错误分类或尚未分类的资料。需要缩小范围时，应把新范围明确写入任务与最终表述。

## 4. 应用强制执行的读取流程

### 第一步：建立分析计划

记录任务 ID、任务类型、问题、绝对时间范围及时区、领域与来源、所需精度、允许使用的状态、指标版本和覆盖要求。相对时间在开始时固定，避免执行期间“本周”含义变化。

同时固定来源读取快照，登记模型输入预算、每页返回上限、单条原文上限和单批任务上限。索引过期时检查变更登记；对受影响范围重建索引，或改用主存的确定性筛选和分页。不能因检索索引尚未更新而漏掉已保存资料。

### 第二步：路由并枚举范围

先查看小型入口，再选择领域和期间。程序返回范围清单、计数、待整理情况与分页游标；模型不能自报“已读完全部”。精确 ID 查询可缩短路径，但不能跳过存在性、状态、范围和修订检查。

主题、关键词和语义检索互补；需要拓展主题或时间时提交范围变更，生成新版分析计划。对于全周期任务，范围清单由可靠时间／来源元数据枚举，不取语义搜索的前若干条作为全部。

时间归属分为确定属于、可能属于和确定不属于。发生时间区间与目标期间重叠的记录进入候选；时间未知或精度不足的记录进入未定范围清单，列出数量和可用信息，不能静默排除。需要时按受控路由核对这些记录，无法确定时在最终覆盖中保留缺口。录入时间仅用于明确以录入时间为条件的任务，不能代替事情发生时间。

### 第三步：按预算读取

执行层按实际输入计算预算，包括指令、历史、索引、工具结果与已选证据，并为输出和后续核对预留空间。每页和单次模型请求都有明确配置上限；配置缺失时不能启动无限制读取。

过长原文按稳定片段位置读取，提供相邻上下文入口；附件独立按需处理。超出上限返回分页与未覆盖信息，不静默截断。未能读取的图片或文件明确计为待处理，不能仅凭文件名判断内容。

### 第四步：分批分析并保存中间成果

大范围任务按日期、来源或事件分片。每批保存提取的观察、相关事件、支持与反例、原文引用、未知项、输入修订及处理状态。成功批次可复用，失败批次可重试；批次完成说明程序取得了有效输出，不证明语义提取绝对完整。

处理台账细到原文片段、结构化字段和附件。范围计划列出各资料应处理的内容单元，登记完成、失败、未读及明确排除的原因；只读长记录的第一片段不能把整条资料标为完成。范围内被排除或未处理的部分仍属于覆盖缺口，不计入已完成数；缩小任务范围需另行登记新版计划。

综合阶段读取这些有来源的结构化成果及指标结果，需要时回查原文。若中间成果仍超预算，则继续分组综合，同时保留原始事件 ID、反例、处理台账和回查路径。多次综合不能增加独立证据数量，也不能丢掉未处理范围。

### 第五步：核对证据与任务覆盖

程序检查引用是否来自本次实际提供的证据、记录是否存在、修订和片段是否匹配、状态是否有效、是否重复计数、统计是否来自指定计算结果。再进行语义核对：引用是否支持该句话，是否把自述变成事实、把局部变成整体、把相关变成因果，是否遗漏已找到的重要反例。

实际输入按每次模型调用登记，不能只记录“整个任务曾读过”。最终新增结论沿中间成果追溯到原始片段；核对该结论的调用必须取得相应原文、重要反例及必要上下文，且仍可分批执行。只有引用字符串或其他批次读过原文，不能代替这次支持检查。相同陈述、来源修订和核对条件下已通过的核对结果可以复用，条件改变时重新核对。

数字结论可以引用确定性计算结果；该结果保留查询范围、口径和原始来源清单，便于复算，不要求把全部原始数值送入模型。模型不能因此声称逐条阅读了所有原始记录。证据链必须能终止于原始资料或有来源的计算结果；互相引用的摘要不能形成循环证明。

另一次模型核对可以作为质量检查，但不是独立真值，也不能以两个模型同意来宣称正确。量化规则由确定性计算核对；对自然语言判断保留人工可查看的依据和纠正入口。

### 第六步：提交提案并决定发布

提案包含结论、引用、范围、处理覆盖、反例和未知项，以及拟改变的观察／洞察或画像采用状态。发布前再次校验相关来源修订、范围版本、删除状态和用户反馈。

达到该类任务的条件才发布对应范围的结论。未达到时可保存部分观察及处理进度，明确缺口；不发布“全周期已完成”或升级长期身份判断。没有新证据的现有画像展示不伪装成一次新分析。

## 5. 覆盖必须分三种说明

| 覆盖 | 说明什么 | 示例 |
| --- | --- | --- |
| 生活记录覆盖 | 真实生活中哪些时期或事项有资料 | 一周只有 4 晚睡眠，其他夜晚未知 |
| 取证范围覆盖 | 本任务纳入的已知资料及其边界 | 目标期间有多少记录，哪些来源未同步或解析失败 |
| 处理覆盖 | 纳入范围的资料实际完成多少处理 | 42 条中处理 36 条，另 6 条仍待处理 |

上述数字仅为格式示例。即使处理覆盖为全部，也不能推出生活记录完整，或证明模型理解没有遗漏。枚举完整只能证明当前主存中符合条件的资料均已列入；搜索式探索不得假称已经穷尽所有相关证据。

每次分析保留计划、范围清单、查询方式、提供给模型的证据 ID／修订、批次结果、遗漏原因、计算版本和发布检查结果。这里记录可审计的输入输出与状态，不要求保存或展示模型内部思维过程。

覆盖统计同时显示资料级与内容单元级进度、未定时间范围的资料，以及未读片段和附件。无法确定是否属于目标期间的资料不擅自放入或移出已确定分母，单独报告其数量和不确定性。

## 6. 维护一致性与写回流程

### 权威保存

原始记录、附件引用、用户反馈、模板版本和已保存的分析修订是权威内容；索引、Markdown 和统计阅读视图是可重建结果。一次保存同时提交记录修订、变更事件、受影响范围和待处理任务，避免“原文保存成功但更新任务丢失”。附件先完整保存并校验，再提交引用。

### 增量失效

分析既记录具体来源依赖，也记录查询范围及其版本。新增、补记、删除、改时间或改主题时，同时检查旧范围与新范围；未分类新记录也进入待整理清单并影响相应期间的覆盖。受影响的指标、洞察、画像、摘要及索引进入待更新状态，无关范围可以复用。

时间推进同样可能使结果失效：指定时区的日／周边界、滚动窗口端点和条目有效期到达时检查受影响范围；用户改变时区也需重新计算相应口径。任务执行期间使用固定时间基准，发布或再次读取当前视图时核对窗口是否仍适用。应用恢复运行时补做错过的到期检查，即使没有新记录也不能无限保留过期的近期状态。

### 提案与幂等处理

AI 不直接修改原文、正式目录、统计数值和当前发布指针。程序验证提案的目标版本、字段、引用、证据类型、口径、用户反馈及允许的状态转换，再保存新分析修订。任务具有稳定幂等标识，重复执行不产生重复观察、行动或画像条目。

### 发布和失败

在临时构建位置生成受影响的文档、索引和引用清单，完整保存后形成不可变的发布包。当前发布指针由权威主存管理；最终的相关依赖、范围、时间有效性、删除和用户反馈检查，与发布指针切换采用同一事务或等价条件提交，并检查预期的当前发布版本。这样可阻止“校验后、切换前”发生的纠错或两个并发构建相互覆盖；条件变化时重新合并或构建，不盲目重试覆盖。

未受影响的内容可以复用，但必须确认其依赖仍有效；不能把不同资料版本的数值与解释随意组合。读取当前内容以主存发布指针为准，不能直接把未完成构建目录当成当前包；纯文件导出从已选定的完整发布包复制。

失败时保留可恢复进度和明确原因。原始记录仍可查看，已失效的旧分析仅作为标明状态的历史内容，不能继续冒充当前有效结论。

## 7. 快照、并发修改与删除

- 一次任务使用固定的来源修订集合、时间基准和口径。多轮检索、分批计算与综合阶段保持一致，不在半途中混入新版本。
- 任务进行期间，相关资料或范围发生变化时，发布检查拒绝将旧结果作为当前结果；对受影响批次重新处理。无关分支变化不必使所有任务重跑。
- 删除与撤回优先于旧快照。每次读取及发布都检查当前删除清单；来源已被删除时，在途任务不能继续返回该来源，也不能把已读取内容生成的新结论发布出去。
- 删除后清理受管原文、旧修订、索引、缓存及派生摘录；其他有效资料仍引用的附件按引用规则处理。回滚发布版本也要检查当前删除清单、用户否定和依赖有效性。
- 受管备份恢复需要合并当前删除记录。只有一份删除前的离线副本且没有后续删除信息时，系统无法知道后来删过什么；已经发给外部的副本也不能自动收回。

## 8. 读取与发布的职责接口

下面定义职责，不绑定具体框架或供应商，也不是已实现接口。

| 职责 | 必要输入与输出 | 约束 |
| --- | --- | --- |
| 建立／扩展计划 | 任务、范围 → 计划 ID、快照、路由、预算 | 扩展范围留新版本和理由 |
| 枚举证据 | 计划 ID、游标 → 元数据页、计数与下一页 | 快照固定；原文不随目录整批返回 |
| 读取证据 | 计划 ID、记录／片段引用 → 有限正文、修订与剩余入口 | 检查范围、状态与预算，登记实际提供内容 |
| 计算指标 | 计划 ID、指标版本 → 聚合结果、样本、排除与来源清单 | 对完整目标数据查询，计算由程序执行 |
| 提交分析 | 计划 ID、结构化结论及证据 → 校验结果／待处理项 | 不直接改原始资料和当前发布版本 |
| 发布结果 | 已通过校验的提案与依赖版本 → 新发布版本 | 属于应用执行层；重新检查并发修改和删除 |

应用不能用“模型说已检查”代替上述记录。用于分析的模型调用不暴露未经约束的文件读取或任意主存写入通道；预算检查适用于最终构建的每一个模型请求。

## 9. 文档路由与外部 AI

导出包保留同样的逻辑协议。`README.md` 解释读取顺序和范围限制，`manifest.json` 指向短目录；增加分片索引：

```text
indexes/
  index.md                       # 索引分片、ID 定位规则及能力说明
  scopes/2026/10/index.md         # 时间范围、各来源数量、待整理项
  evidence/2026/10/page-001.md    # 有限证据元数据和下一页入口
  ids/index.json                 # 小型 ID 分片路由
  ids/<shard>.jsonl              # 有限映射；大分片继续拆分
data/
  analysis-runs.jsonl            # 完整迁移用的分析计划、覆盖与发布记录
```

范围与证据索引允许继续分页，单页大小由导出协议固定。ID 分片不要求模型读取全量 `data/catalog.jsonl`；后者是完整迁移数据，不是默认上下文入口。文件中的相对路径、ID、修订和下一页引用需要自动校验。

三种使用能力要明确区分：

1. **通过本 App 的检索接口访问的 AI**：由接口强制执行路由、预算、版本和证据登记。
2. **具备文件读取工具的外部 AI**：可按文档逐层查阅；仅靠 README 无法强制它遵守，也不能保证其平台不会一次加载整包文件。
3. **只能接收一次输入的 AI**：由 App 根据任务导出有限证据包，附范围、来源、覆盖和未纳入内容。它不能自主查询包外资料，不能称已读取完整知识库。

强制性由应用执行层保障；文档负责可移植的导航与约定。不会把文件内的说明误称为对任意外部 AI 的技术控制。

## 10. 验收与质量评估

实施时建立小规模、可人工核对的任务集合，分别评估取证、计算、解释和维护，不能只检查最终文字是否流畅。

- 整库增长后，入口和单页仍有上限；任一模型请求都在预算内，超限会拆批或返回未完成状态。
- 能沿时间、主题或精确 ID 找到同一记录；错误标签和未分类资料不会从全周期范围枚举中消失。
- 时间区间跨越目标周期的记录进入候选，日期未知的记录单列缺口；补录日期后相关旧／新范围正确失效。
- 统计结果覆盖全部合格数据，和确定性参考计算一致；相似度前几条命中不会被当作分母。
- 多批分析有可核对台账，失败或不可读附件进入缺口；模型不能伪造完成页数与处理覆盖。
- 关键反例位于长记录末尾时，仅处理开头不能将整条记录标为完成；综合核对需要取得原始片段与该反例，而非只核对中间摘要。
- 引用定位到实际提供的记录修订与片段；构造“引用存在但不支持结论”的案例，语义检查能够识别或交由复核。
- 同一事件多次总结不重复计数；反例、自述改变和用户已否定的解释不会被静默丢弃。
- 记录提交后立即退出，重启仍能恢复待处理任务；重试不产生重复内容。
- 周报完成后补记上周事件，即使从未被旧周报引用，也能使相关范围失效；改到本周时两周均更新。
- 生成中来源从第 2 版改到第 3 版，旧任务不能覆盖当前结果；图表和文字解释使用一致版本。
- 最后校验与提交之间插入来源修改、删除或另一发布，条件提交会拒绝旧构建；两个同时完成的构建不会互相覆盖已提交的新内容。
- 没有新记录但跨越日界线、滚动窗口或有效期时，当前趋势和近期状态仍正确失效；离线期间到期后重新打开应用也会检查。
- 删除发生在生成或发布期间时，旧任务发布失败；回滚或受管恢复不能重新公开已知已删除的内容。
- 当前摘要引用过期或撤回判断时，发布检查失败；单纯请求查看历史则明确展示其历史范围。
- 外部任务包明确说明资料范围，不能把部分证据包装成全量画像分析。

评估分别记录：已知证据的召回、重要反例的遗漏、引文支持程度、数字一致性、来源修正后的传播、范围表述与实际覆盖是否一致。第一版需在真实且可核对的个人使用任务中验证这些能力；流程完成不等于结论永远正确。

## 11. 研究依据

[RAPTOR](https://arxiv.org/html/2401.18059v1)研究了多粒度摘要与检索，其主实验采用跨层检索，不证明固定层数或机械逐层遍历最佳。[Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)显示受测模型并不总能可靠利用所有长上下文，不能据此推断所有最新模型相同。

本协议的固定职责层次、强制预算、证据覆盖、版本和发布检查是产品工程约束。具体核验范围见[分层检索与可靠性研究](../../research/2026-10-16-hierarchical-retrieval-reliability.md)。
