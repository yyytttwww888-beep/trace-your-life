# Trace Life：移动端页面与文案优化

用户已指定以 Codex app 的简洁风格与操作逻辑为参考，优化现有 Android 页面，减少 AI 及实现术语，保持个人记录应用的小体量。本轮沿用工作区已有单色配色、原生控件及启动图标，不改写后端协议。

## 现状与取舍

现有首页在记录列表前放了完整筛选表单和八个导航按钮；写记录先填写日期、主题，正文排在后面。页面多数内容包在同权重卡片中，标题、返回按钮随正文一起滚动。一些详情仍直接展示 UUID、英文状态或协议字段。

仅调整颜色无法改善这些操作负担；引入 Compose 或重新实现所有流程会扩大此次改动。采用现有原生控件上的布局整理：固定顶栏、侧边导航、内容优先、按需展开选项。Codex 只作为视觉及导航参考，不引入对话入口或编程任务概念。参考：[官方介绍](https://openai.com/index/introducing-the-codex-app/)；本产品的布局是针对手机记录场景的设计选择。

## 页面与交互

- 首页：顶栏品牌与菜单，简短记录入口，最近记录列表；日期／主题／归档筛选折叠，展开后保持原有查询行为。侧边导航组织记录、回看、资料入口，所有已有页面可达。
- 编辑：正文与复盘问题在前；日期、主题等补充信息按需展开，原有日期未知、日期区间、图片、历史模板绑定与草稿恢复保留。保存有明确反馈，离开未保存内容仍需确认。
- 共用框架：返回与页面名固定在顶部，正文独立滚动；触控目标至少 48dp，适配系统栏、键盘和深浅色。已有页面保留功能和 view tag；展开区只控制可见性，不丢弃已填表单。
- 看板／知识／行动：结果优先，筛选与设置放在展开区。缺失健康数据如实说明，不制造趋势或评分。
- 整理／回顾／关于我／设置／备份：简短中文说明，内部编号和诊断明细按需查看。保留来源不足、失效、确认／纠正／否定、保存为候选与明确采用的不同意义。
- 云端整理：名称可以简化，但操作前仍说明将发送所选记录给 DeepSeek，可能产生费用；自动整理开启须明确确认。密钥不显示为技术教程，不隐藏凭据保存边界。

## 视觉约束

沿用黑白灰与少量语义状态色、系统中文字体。层级通过字号、留白与分组表达，减少重复描边和大面积按钮。页面不放虚构统计、装饰图像、营销标语或 AI 品牌词。主操作使用反白按钮，次操作用轻量文字或列表行。

## 实施与验收

1. 保存现有工作区及修改前 APK，准备独立模拟器与合成数据。
2. 实现共用顶栏、侧边导航、展开区，调整首页及编辑顺序；并行清理其他页面结构与文案。
3. 运行原有记录操作测试，补充导航、展开筛选与草稿恢复的行为验证；执行 lint 和 APK 构建。
4. 在 Android 模拟器安装，检查首页、菜单、写记录、保存后列表和主要页面，截图深浅色、键盘与小屏／字体放大情况；不把模拟器验证称为实体手机验证。
5. 更新开发文档和路线，交付可安装 APK 及可复现模拟方式。外部环境问题记录实际结果，不用静态网页代替真实 Android 运行截图。

原始记录和派生知识的维护规则、数据库格式及受控取证不变。当前尚未接入的流程不借此次美化宣称完成。
