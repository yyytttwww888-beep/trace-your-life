# 跨期经验、历史意见与分析归档

日期：2026-10-20。承接用户已确认的下一轮三项工作；实现与验证状态见 README 和开发路线。

## 要解决的问题

一周一条总结仍不足以串起人生经历。相同经验在后续得到补充、遇到例外或被替代时，需要一个持续入口；用户以前纠正过的解释需要影响新分析；完成任务需要收起，同时长期保留正式知识和核对过程。

## 经验线索

以用户命名的稳定线索连接固定知识修订，保留 INITIAL、SUPPLEMENT、EXCEPTION、NARROW、REPLACE 的不可变事件。第一项为起点；其后的最新起点、收窄或替代代表目前采用的理解，补充和例外不自动改写它。例外、收窄或替代必须写明用户理由。

新关联必须来自当前有效知识。历史来源后来失效时明确显示待核对，不退回旧解释冒充当前结论。删除来源后不复制、恢复其机器正文；用户独立说明继续保留。线索的关联关系不是新证据，也不改变原知识的分析范围、版本、反馈或发布凭据。

主题档案和知识详情均可进入线索，查看变化过程，或将有效知识加入已有线索。完整备份保留线索、事件及永久删除台账；恢复时保留本地已有同一线索，不把旧备份覆盖为较早理解。

阅读包提供分页经验导航和固定知识链接，只展示同包纳入的知识。范围外、已删除或非当前知识不复制正文；相关事件的说明也不能越过导出范围泄漏。导出明确标明省略数量和目前采用理解是否在包内，不通过缺失事件推导新的当前理解。

## 历史意见进入新分析

从本次原文的全部主题路由相关历史否定、纠正与撤回；无法确定主题的独立意见保守纳入。先固定反馈目录与版本，再在单次输入预算内读取内容。它是控制背景，不登记为证明新结论的原始证据。任务最多固定 1000 个反馈引用；生成请求最多带入 8 条，界面分别显示总数和本次生成参考数，不宣称模型读取过全部意见。

每条新发现发布前，用户须分页逐项对照所有相关意见，选择已遵守、不适用或仍有冲突，并保留理由与版本。尚未处理或仍有冲突时禁止核对发布；不适用必须有明确理由，不能批量跳过。此人工语义门槛独立于原文核对，避免仅依赖提示词或字面匹配来宣称“理解正确”。第 17 条意见仍可分页处理，不因单页限制成为永久堵点。

逐项对照的手写理由同时进入独立保存区，可按分析分组分页查看；来源或分析被清理后仍保留。明确永久删除整组说明会同步清理其机器派生链，并写入删除台账。恢复保留本机较新的选择和理由；若旧备份的核对采用更早的对照结果，旧任务不能恢复为当前。

意见新增、修改或删除后，受影响任务与知识须重新核对；请求开始与返回发布均检查固定版本。删除旧来源时传播到实际读取其内容或人工对照过的后续任务；仅列入目录但未使用的引用使任务失效，不扩大正文清理范围。删除传播，独立用户文字与机器引用分别处理。恢复旧备份不能重建已删除正文或把过期反馈凭据重新视为当前。

## 分析归档

归档是任务生命周期属性，保留现有任务身份和全部证明载荷。不能归档正在请求的任务；继续分析或核对前必须恢复为活动任务。归档和恢复使用版本检查，仅在本地执行，不能自动调用模型。

活动任务维持 100 项、16 MiB；归档任务独立限制 10000 项、64 MiB。任务列表先按类型和归档状态查元数据，再读取当前页，避免先取前 100 个任务而永远看不到更早结果。任何容量边界明确报错，不静默丢弃旧知识或任务。

归档不改变来源有效性。否定、纠正、源记录修改或删除仍能传播到归档任务及其正式知识。完整备份包含归档任务；阅读包不复制内部分析过程，但归档任务支持的有效知识仍可导出。恢复旧格式时任务均为活动状态。

## 验收

- 跨三周将知识作为起点、补充、例外及收窄，重启后保持固定身份和明确当前理解。
- 来源修订、删除与旧备份恢复后，不出现已删除机器正文；独立说明仍可读取。
- 相同主题的新分析读取历史意见，显示实际覆盖；超过一页仍可处理；未处理或冲突时不能发布。
- 意见变更、并发修改及删除使旧凭据失效，不能通过直接底层发布或恢复绕过。
- 至少 417 个合成分析任务分批归档后仍可分页回看；有效知识、反馈、原文依据与备份恢复保持一致。
- Android 页面完成关联经验、纠正意见、逐项对照、归档与恢复操作；自动测试、APK 构建和模拟器验证分别报告。
