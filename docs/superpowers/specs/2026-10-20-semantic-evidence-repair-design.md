# 语义核对与知识保存修复

用户要求立即修复真实测试中出现的误读、误拒、未知项矛盾和画像因果升级。本轮沿用现有功能范围，不等待新的产品确认。

## 诊断依据

第五轮真实报告已经完整提供原文与目标，故不能把这些错误归因于未读取全库。核对只有来源 ID 和自由理由，未要求把具体原句与目标含义对应；生成未知项又不属于逐条发布核对目标。统一生成语义规则主要放在用户 JSON 内，画像叶使用另一套规则，顶层提示没有统一执行同样的区分。证据见[原始评审](../../reviews/2026-10-20-complete-daily-knowledge-quality-review.md)。

## 实施选择

只加长提示或默认切换模型无法解决来源约束和未核对附加文字的问题。本轮增强供应商的输出契约，保留领域存储与历史任务格式：

1. 核对每个固定段落时标明事实、条件假设、未来建议、限制或混合陈述，给出本次原文的准确引文与字段位置，再判断支持、缺据或反证。程序验证引文确实存在于对应来源，不能拿 ID、哈希或模板提问充当个人证据。
2. 对照时间量的含义、执行与计划、否定、范围和因果强度。未来建议核对依据和边界，不要求已经执行或有效；资料没说明不能当作反证。模型整体拒绝仍不自动提升为支持。
3. 新生成结果不返回独立生活未知；`unknowns` 可省略或为空数组。实际影响结论的限制和待确认问题写入有来源的陈述，随正文进入核对；资料读取覆盖继续由程序展示。违反新契约的响应拒绝保存，不静默删除内容。历史任务的未知项不改写。
4. 顶层生成规则与画像叶、跨批归并规则一致；跨批只整合已提供的派生材料，不增强上游因果强度，不因缺少逐日日记否定明确周总结，不要求补造遗忘的历史。
5. 更新供应商身份，旧失败请求不得以新提示冒充同一次重试。所有新增指令与输出仍计入现有范围、快照和预算；不新增隐藏模型调用。

实际请求只在根级 `system` 指令字段移除已经完整出现在真实系统消息中的相同程序常量；原始 `ModelRequest`、证据、问题、反馈及派生内容不改写。核对先生成完整 `target.parts`，再做同样的指令去重。发送包、预算与请求哈希始终使用同一份最终字节，不放宽默认输入预算。

逐命题保留主体、关系、模态及范围：模型提出的可能解释不能变成“用户认为”；旧反馈的条件不能移植到本次事件；数值本身不证明充足或不足。一个画像候选仍可包含多条短句，事实归属与保守限制分开表达，避免用限制段落的总标签盖过内部事实。解释分类允许领域已有的 `POSSIBLE_INTERPRETATION` 用语，但不改变支持／反证必须有真实锚点的门槛；未来建议引用它所针对的原始问题，不要求新步骤已发生。

三轮真实检查仍发现逗号连接的事实前提被保守尾句掩盖，故把程序分段扩至中英文逗号，保留数字千分位、小数、全部标点与原顺序，仍最多 24 段；必须结合完整目标理解各段的主语、条件和范围，不能将条件句断开后误判。新任务输出预留明确提高至 8,000 token，支持更细片段及引文回复；输入范围、预算和最大输出字节不放宽，旧任务与备份额度不改写。模型仍用 FLASH 非思考模式，思考／PRO 配置的有限对照未形成采用依据，所有失败另行保留。

第四轮真实核对又暴露两种来源契约问题：正确的发生日期被当时的字段白名单拒绝；长文完整提供后，一段连续引文跨越了固定片段边界。现有协议允许引用本次已提供的 `/startDate`、`/endDate`、`/zoneId` 完整字符串，仍不允许截取年月、状态前缀或引用缺失值。时间字段只表达记录自身的时间，不赋予自述额外真实性。

跨片段正文匹配只处理当前请求已提供的文字：同一记录、修订、原字段和总码点数，片段位置及实际码点长度一致、互不重叠，实际匹配区间首尾相接，并与模型指定的凭据区间相交。所有匹配涉及的凭据纳入归一后的支持／反证依赖，已发送凭据继续完整登记；不额外读取邻接片段，不跨缺口或版本补全，也不扩展用户范围、输入预算或提取覆盖。这是对已读资料的精确引用支持，不是允许模型自行拼写或合成证据。

核对提示进一步要求 `checks` 内先给 `anchors`、对照 `reason`，再决定局部 `status`，最后给整体 `verdict`。该顺序是提示改进，解析器仍按字段集合和值执行来源与一致性校验，不把JSON键顺序当作模型真实推理过程。第四轮已证实细分段和真实引文仍可能伴随时长与观点归属误读；日期和跨片段匹配修复不能被宣传为这些语义问题已经解决，须继续保留独立复评的失败与发布状态。

## 验收

先复现旧响应可通过的协议缺口，再验证新协议拒绝无锚点、伪造引文和未核对未知项；保留合法建议、假设、指标和行动来源。固定六例、十一挑战与画像资料及语义预期不变，新增加未见表达的正反对照，全部保留真实请求与失败，不挑选成功轮次。报告程序检查和独立语义阅读结果，不能用引文存在证明含义正确。最后运行相关回归、完整测试、lint、构建并发布同签名修复 APK。
