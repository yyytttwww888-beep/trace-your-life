# Trace Life：个人知识库与复盘设计草案

日期：2026-10-16。状态：供评审的设计草案，尚未开始应用实现。

## 1. 已确认的需求

- 个人自用、运行于 Android 手机；具体机型和系统版本尚未核实。
- 输入包括自由随记、可选的每日复盘、餐食照片，以及期望接入的华为运动健康睡眠与运动记录。
- 允许零散、不完整和事后补记；知识逐渐积累，按需从概览深入到主题、周期和具体证据。
- 第一版不做历史资料导入；支持导入用户自己的复盘模板。
- 知识组织必须可维护、可定位、可迁移。不同 AI 在具有文件读取能力时，应能理解入口、按需查阅和核对来源。
- 复盘需要有成熟方法依据，能形成学习、调整和后续验证，不能只有流水账。
- 提供数据看板，用图表直观展示关键数据的趋势与关键信息，聚焦少量重要指标，并能追溯对应记录。
- 形成长期个人画像，研究其维度与分析方法，持续沉淀价值、背景、偏好、行为模式和变化，并区分近期状态与长期倾向。
- 强制通过分层索引和路由按需取证，禁止一次性把全部知识库送入模型；维护一致性、证据覆盖和分析校验必须由应用执行流程保障。

领域词汇统一见 [CONTEXT.md](../../../CONTEXT.md)。健康接入与饮食依据分别见[华为接入研究](../../research/2026-10-16-huawei-health-integration.md)和[饮食分析研究](../../research/2026-10-16-dietary-photo-analysis.md)。

## 2. 架构选择

| 方案 | 优点 | 主要代价 |
| --- | --- | --- |
| Markdown 作为主存 | 文件容易阅读，直接交给其他 AI | 时间统计、跨文件引用、模板版本和纠错传播需要大量额外约束 |
| 仅结构化主存 | 一致性、查询和修订容易管理 | 其他 AI 需要专门工具才能理解与访问，迁移阅读体验弱 |
| **结构化主存 + 自动生成的 Markdown 知识包** | 管理可靠，阅读与迁移开放，目录和引用可以统一生成 | 需要维护导出格式，并明确主存与生成文件的关系 |

推荐第三种。Android 本地的结构化资料和受管附件共同构成一套权威资料；Markdown、目录索引、检索索引和看板指标是可重建的阅读视图。AI 分析结果也要保存内容、依据和版本，导出只渲染已保存结果，不重新生成结论。

第一版通过 App 修改权威资料，再生成文档；外部修改 Markdown 不会静默回写主存。未来需要双向编辑时另行设计显式修订和冲突处理。用户模板导入是本版本支持的明确入口，不等同于任意知识文件回写。

所有用户查询与后台 AI 分析遵循[分层检索与维护可靠性协议](2026-10-16-knowledge-routing-and-reliability-design.md)：先固定任务范围与来源快照，再受控读取、分批处理和校验发布。文档提供导航，应用工具层执行预算与范围限制；不能只用提示词代替强制约束。

### 数据存储与导出

第一版建议以手机本地为主：结构化资料保存在 SQLite 数据库，餐食照片等原始附件保存在应用私有的持久目录，由稳定 ID 关联。原始记录、观察、已保存分析、画像及反馈、模板版本与证据关系共同构成权威资料；缓存不能承担主存职责。电脑、NAS 或个人网盘可以保存用户导出的副本，第一版不引入多个可同时修改的主库，也不默认建设云端业务数据库。

Android 的应用私有存储会随卸载清除，因此可恢复备份必须保存到应用私有目录以外。导出通过系统文件选择器让用户选择保存位置；可使用设备本地目录或系统中已接入的文档服务，再自行复制到电脑、NAS 或网盘。不能据此承诺所有 NAS、网盘都支持直接写入。依据：[应用专属存储](https://developer.android.com/training/data-storage/app-specific)、[系统文档选择与保存](https://developer.android.com/training/data-storage/shared/documents-files)。

“本地主存”与“完全离线分析”分别约定：如果使用云端模型，仍需发送任务选中的必要文字、图片或证据；模型服务及其保留策略需在选型时核实。系统自动备份和设备迁移也必须显式配置。建议核心资料默认不进入系统自动云备份，并对设备迁移设置相应排除规则，以应用自身的完整备份作为恢复途径；Android 部分厂商的设备迁移行为不能仅靠一个开关判断，需在目标手机验证。依据：[Android 自动备份及迁移规则](https://developer.android.com/identity/data/autobackup)。

导出入口建议为“设置 → 数据与导出”，明确区分四种用途：

| 导出类型 | 格式与内容 | 用途与完整性 |
| --- | --- | --- |
| 完整恢复备份 | 默认加密；带格式版本的结构化资料、原始附件、有效保留的修订、模板版本、已保存分析、证据关联、用户反馈、配置与删除记录 | 用于换机或重装恢复；索引可重建，登录凭据及模型 API 密钥不随包导出 |
| AI 阅读知识包 | ZIP 内含分层 Markdown、JSON／JSONL、索引和 manifest；附件是否包含明确可选 | 用于个人归档或交给其他 AI 按层定位；只有内容完整并通过恢复验证的包才可兼作迁移备份 |
| 指定范围证据包 | 按问题、主题或时间导出所需资料、原始依据、必要上下文及覆盖说明 | 例如最近四周睡眠及相关工作记录；缺失或省略内容须标明，不作为完整备份 |
| 指标与报告 | 指标 CSV、复盘或分析 Markdown | 用于表格处理与阅读；包含单位、统计口径、时间范围及覆盖信息，不作为完整备份 |

加密备份必须能在新手机独立解密，采用用户掌握的恢复口令或独立恢复密钥，不能仅依赖旧设备的密钥。恢复时先校验格式版本、文件校验值及引用关系，再整体提交；模型 API 密钥和登录状态重新配置。备份恢复属于第一版数据保全能力，与暂不支持的历史资料导入分开。

所有导出固定一个来源快照，manifest 保存范围、格式版本、附件清单和完整性状态。数据库与附件必须一致，不能直接复制正在写入的数据库文件就宣称已完成备份；数据库快照可采用受支持的备份机制，附件另行绑定清单校验，依据：[SQLite 备份机制](https://www.sqlite.org/backup.html)。发布导出前复核删除状态；受影响时重建或中止。恢复还须合并目标设备已知的删除记录，但不能从删除前的离线旧备份推知后来的删除。已导出的外部旧副本由用户管理。

## 3. 内容模型与维护约束

| 内容 | 保存内容 | 维护原则 |
| --- | --- | --- |
| 记录与附件 | 原文、照片、授权同步数据，来源、发生时间、录入时间 | 原始输入与后续修订可区分；来源性质明确 |
| 观察 | 有记录支持的描述或结构化值 | 区分自述、测量、AI 估计；用户确认另设状态，不改变原来源性质；估计保留假设 |
| 知识条目 | 概念、方法、经验、适用情境和引用 | 保留用户原意；提取或整理不等于已掌握 |
| 洞察 | 模式、解释、假设及其依据 | 保留不确定性、适用时间与有效状态 |
| 复盘 | 期望、实际证据、原因假设、经验与行动 | 绑定模板版本；AI 草稿和用户确认的内容可区分 |
| 行动实验 | 具体调整、触发条件、预期变化、回看时间、实际结果 | 下次复盘检查上次行动；用户决定是否采纳 |
| 主题档案与个人概览 | 当前状态、关注点、有效洞察与导航 | 是派生视图，每项判断最终可追溯到原始记录 |
| 个人画像与条目 | 跨周期的个人理解、情境范围、用户反馈及发布版本 | 条目引用观察或洞察，保留支持、反例和适用期；宽泛的身份解释经核对后进入默认摘要 |
| 指标口径与看板偏好 | 指标含义、来源、单位、计算规则、版本和关注顺序 | 图表与复盘共用口径；计算结果和图表均属于派生视图 |
| 分析计划与执行记录 | 范围、来源快照、读取预算、证据清单、批次覆盖和发布检查 | 程序记录实际取证与处理状态；AI 不自行宣称已经读完所有资料 |

统一约束：

1. 每项资料有稳定 ID 和修订版本，目录移动或标题更改不会改变身份。引用至少定位到资料 ID、修订版本和相关字段或片段。
2. 分别保存发生时间和录入时间；时间可表示日期、区间或未知，不能为零散记录编造精确时间。统计口径明确采用的时区。
3. 主题是关联关系，同一条记录可关联工作、睡眠等多个主题，不为分类复制原文。主题别名和合并由系统管理，避免近义标签分裂。
4. 按需提取观察和知识，不强求每条随记都填写所有字段，也不要求每条观察生成一个独立 Markdown 文件。
5. 结论保存依据和生成时间；可选保存模型、指南与模板版本用于核对。模型自报置信度不能直接当作已校准的准确率。
6. 摘要可以作为导航或分析上下文，但已有洞察不能重新计作独立原始证据。画像判断必须保留到原始记录的证据路径。
7. 已确认的用户回答与 AI 派生段落分别管理。重新分析可以更新派生段落，不能覆盖用户已确认的文字。

## 4. 知识包：固定目录、双重入口、一份内容

下面是生成文件的组织约定，不要求现在创建所有空目录。目录只随实际资料出现；索引按时间分段，避免一个文件无限增长。

```text
knowledge/
  README.md                     # 阅读顺序、来源解释、定位方式
  manifest.json                 # 格式版本、导出时间、范围、完整性信息
  overview.md                   # 当前目标、关注点、阶段状态
  metrics.md                    # 已启用指标说明、近期汇总、覆盖与记录引用
  indexes/
    index.md                    # 分层路由、索引分片与精确定位入口
    scopes/2026/10/index.md      # 范围、来源数量、待整理项
    evidence/2026/10/page-001.md # 分页证据目录与下一页入口
    ids/index.json              # 小型 ID 分片路由
    ids/<shard>.jsonl           # 有限 ID 映射，必要时继续拆分
  profile/
    index.md                    # 当前画像与八个维度的阅读入口
    <dimension>.md              # 具体维度的当前条目、情境及依据
    history/index.md            # 历史变化与发布版本入口
    history/2026/10.md          # 当月变化，链接相应条目版本
  topics/
    index.md                    # 主题目录
    sleep.md                    # 睡眠主题档案与相关时间入口
    nutrition.md
    movement.md
    work.md
    learning.md
  timeline/
    index.md                    # 年/月入口
    2026/10/index.md             # 本月日记录和周复盘入口
  records/
    2026/10/<record-id>.md       # 原始记录、修订、关联与观察
  reviews/
    daily/2026/10/2026-10-16.md  # 当天记录概览和当日复盘（若存在）
    weekly/2026/2026-W42.md      # 周复盘、记录覆盖和行动回看
    events/<review-id>.md       # 重要事件复盘
  notes/
    index.md                    # 可复用知识的主题入口
    <knowledge-id>.md
  actions/
    index.md                    # 当前行动与历史月份入口
    2026/10.md                   # 行动实验及回看结果
  templates/
    index.md
    <template-id>/<version>.md  # 问题、意图、来源、适用范围
  data/
    catalog.jsonl               # ID、类型、版本、阅读路径的映射
    records.jsonl               # 用于迁移的结构化资料，其他类型同理
    reviews.jsonl
    knowledge.jsonl
    insights.jsonl
    actions.jsonl
    templates.jsonl
    relations.jsonl
    metric-definitions.jsonl    # 指标口径与版本，计算结果可由原始资料重建
    dashboard-preferences.json # 用户关注的指标及顺序
    profile-entries.jsonl       # 画像条目及修订，引用观察／洞察
    profile-releases.jsonl      # 采用的条目版本、用户反馈关联及变化说明
    analysis-runs.jsonl         # 分析计划、证据与覆盖、批次和发布检查记录
  attachments/
    <attachment-id>.<ext>
```

时间入口和主题入口链接同一份记录。知识条目只保留一份正文，主题页维护关联和简短说明。日页面可以列出当天随记、餐食和健康数据，即使当天没有填写复盘，也不伪造一份已完成复盘。

README 约定外部 AI 的阅读路径：先读小型入口与协议，再根据任务选择当前画像、主题或周期；进入范围索引、分页证据目录，再按需读取原文。精确 ID 查询经范围验证可直接定位，不必机械遍历每层。候选和历史画像按明确范围另行读取，不混作当前定论。完整 catalog 和结构化数据用于迁移，不作为默认上下文；精确定位使用受控接口或 ID 分片索引。所有生成文件的相对链接、分页和 ID 映射应可验证。

manifest 明确导出时点、内容范围及是否包含完整结构化资料和附件。完整迁移包包含恢复内容和关联所需的资料，不仅是摘要；指定范围证据包及内容不完整的阅读包明确标为不可完整恢复。模板旧版本和记录修订随完整迁移包保留；明确删除的内容不进入新的导出。导出与恢复规则见第 2 节“数据存储与导出”。

## 5. 更新、纠错与恢复

- 新记录先可靠保存，再进行 AI 整理。网络或模型失败时，原始记录仍可查看；重试不会重复创建同一记录或多条相同行动。
- 编辑产生新修订。引用旧修订的当前洞察、摘要、主题档案和概览被标为待更新，再按依赖关系重算；更新完成前不把旧判断当作当前有效结论。
- 周期分析同时保存时间范围、主题筛选和记录覆盖信息。新增或补记资料、删除资料、修改发生时间或主题时，涉及范围的当前分析同样待更新，即使新资料尚未出现在旧证据引用中；其上层档案和概览沿依赖关系更新。
- 看板与复盘使用同一套指标计算结果及口径版本。原始资料变化后，相关图表、统计汇总和变化说明一起失效并更新；生成中的旧说明明确标为待更新。
- 历史复盘保留“当时的判断”，同时标注证据后来发生了修正；用户已确认的回答保留原文。当前视图提供更新后的分析，两者可区分。
- 同步数据根据来源与记录标识识别重复，处理源数据修订；设备观测与同日手写感受并存，不能互相覆盖。
- 删除要同步处理附件引用、索引及相关派生内容，必要时重算。生成包在完整构建和引用校验通过后替换；已发送到外部的旧副本无法自动回收。
- 归档仅从活跃入口隐藏资料，历史与导出仍保留；删除清理目标及其旧修订，未被其他有效资料引用的附件随之清理。删除优先于历史保留：历史引用可显示“来源已删除”，复制的来源内容和受影响的派生段落需要移除或基于剩余依据重算。其他独立编写、未被删除的用户回答不自动改写；若要移除整份复盘，则删除该复盘及其修订。
- 索引可重建；生成文档可从保存的资料重建。恢复验证应覆盖原始资料、附件、模板版本、证据关系和已保存分析，不以“文件已导出”代替可恢复性验证。
- 保存记录与登记待处理任务必须同时提交；任务固定来源快照并具有幂等标识。AI 先提交变更提案，程序检查引用、口径、范围与用户反馈，发布前再检查相关依赖是否变化。
- 文档和索引完成一致性校验后通过条件提交发布；最终依赖、删除和反馈检查与发布指针切换不可分割。滚动窗口、有效期和时区变化也触发失效，不以有新记录为前提。删除状态优先于快照、回滚和受管恢复；旧任务不得发布包含已删除来源或其派生摘录的新结论。详细竞态与失败恢复规则见检索可靠性协议。

## 6. 有深度但可持续的复盘

建议把共同骨架定义为：**期望 → 实际与证据 → 差距与影响因素 → 可复用经验 → 下一步实验 → 后续回看**。这是为本产品综合形成的框架，不宣称是所有企业采用的统一模板。方法来源与适用限制单独记录在研究笔记中。

| 方法依据 | 采用的思想 | 个人适配边界 |
| --- | --- | --- |
| [WHO：行动后回顾（AAR）](https://www.who.int/emergencies/operations/emergency-response-reviews/after-action-review) | 回顾发生了什么、有效做法、问题、原因与改善 | WHO 文档用于事件与公共卫生响应；这里借用其问题框架，不称其为官方个人成长模板 |
| [Google SRE：无责复盘](https://sre.google/sre-book/postmortem-culture/) | 理解当时掌握的信息和情境，寻找可改善的系统条件，形成后续措施 | 原场景为系统事件；在个人事件复盘中借鉴，不能推出 Google 员工每天使用同一模板 |
| [IHI：PDSA 改进循环](https://www.ihi.org/library/model-for-improvement/testing-changes) | 说明预测，小范围尝试，对照观察，再调整下一轮 | 原场景为改进实践；用于个人行动实验，不把一次观察直接视为确定因果 |

来源与设计综合的完整区分见[复盘方法研究](../../research/2026-10-16-reflection-methods.md)。

### 每日复盘：围绕一个值得理解的事件

建议默认约 5–10 分钟，时间仅是使用建议，不设为完成要求。所有问题可跳过，用户可改写；已有记录供用户核对，AI 不代填个人动机或确认不存在的事实。

1. **回看昨天的行动**：原定调整是否发生？实际结果是什么？未发生时，缺少了什么条件？
2. **期望**：今天最重要的事情是什么？原本希望出现什么结果，为什么值得做？
3. **实际与证据**：实际发生了什么？有哪些具体产出、行为或感受支持这个判断？哪些没有记录？
4. **解释差距**：哪些做法起了作用，哪些因素造成偏差？区分已知事实、自己的假设、可控因素和外部条件；有没有其他合理解释？
5. **提炼经验**：今天形成了什么可复用的认识？它适用于什么情境，哪些情境不适用？有什么值得保持？
6. **下一步实验**：明天或下个合适场景只改变什么？什么时候触发，怎么做，用什么迹象判断有效，何时回看？
7. **个人状态（可选）**：这件事对精力、身体、情绪或关系有什么影响？有没有值得保留的愉悦、恢复或连接？

自由写作同样可保存；AI 可以把已有信息映射到这些问题，把缺失处留空。深度来自证据、解释与回看，不来自填满每一个问题。

当天没有预设目标时，可以选择一次决定、意外事件或值得保留的体验作为复盘对象，不事后编造目标。休息与维持状态可以是合理结果；没有新行动时允许结束复盘。

### 每周复盘：检查模式与方向

建议默认约 20–30 分钟，可拆分完成。

- 本周真正重视的目标是什么？投入时间与精力的方向和它一致吗？有没有必要调整目标本身？
- 有哪些成果、实践、认知变化或恢复迹象？分别有哪些证据，哪些只是主观感觉？
- 上周行动实验的执行与结果如何？应该继续、调整、停止，还是因资料不足暂缓判断？
- 哪些顺利与卡点反复出现？工作安排、环境、睡眠和饮食是否出现共同变化？相关性不能直接当作因果。
- 学到的内容中，哪些真正应用过或形成产出？哪些仍只是收藏或理解？
- 下周保持什么、减少什么、尝试什么？优先选择一到两项可检查的行动。

### 重要事件复盘：成功和失误都可以复盘

围绕项目、决策或明显异常事件整理目标、关键时间线、结果与影响、已有预案、起作用的因素、促成问题的条件、可复用经验和后续措施。允许多个促成因素；不强制寻找唯一根因，不用“自律不足”等标签代替解释。

## 7. 用户模板导入与版本

第一版建议支持 Markdown 文件与粘贴文本两种方式。流程是：导入原文 → 解析问题 → 展示预览 → 用户确认 → 保存模板版本。原文保留，解析失败或无法明确映射的内容仍可作为自定义问题，不静默丢弃。

一个模板包含名称、适用周期或事件、方法说明、问题顺序、每个问题的稳定 ID 与意图、可选的填写提示、来源、版本和适用说明。问题默认可选，用户可以调整。只有意图和口径一致的问题才适合跨模板比较；未知映射保留为自定义项，不强行套进内置框架。

涉及数值或等级时还需记录单位、时间范围和统计含义，例如“学习时长”与“专注学习时长”不能自动合并为同一条趋势。模板变更后的比较仅在口径兼容或有明确换算规则时进行。

每份复盘绑定当时的模板 ID、版本和题目文本，回答关联问题 ID。修改模板产生新版本，只影响新建复盘；旧复盘保留原问答。已被历史复盘引用的模板第一版提供名称明确的“归档”操作；不能把保留旧内容的操作称为“删除”。未被使用的模板可以删除原文与全部版本；若要彻底删除已使用模板，需先明确处理其引用复盘，不能自动误删历史。

模板中的分析偏好可以保留供用户确认，但不获得修改原始资料、自动采纳行动或绕过证据规则的权限。第一版以理解并保存问题为重点，不扩展成可执行脚本或复杂流程平台。

## 8. 数据看板：关键趋势与行动回看

### 展示范围

默认展示 **3 个关键趋势卡片 + 1 个行动回看区**。用户可调整关注的指标和顺序，其余维度通过主题入口查看。初始建议关注睡眠、运动和饮食；尚无数据或来源未连接时展示真实状态与记录入口，用户可以替换为工作或学习维度。

每张卡片只保留一个主要趋势、当前期间的观察汇总、记录覆盖说明，以及在证据足够时提供的一句变化解释。解释属于 AI 洞察，需关联计算结果和具体记录；没有可支持的变化时不生成解释。

| 维度 | 关键内容 | 图表或表达方式 | 适用条件 |
| --- | --- | --- | --- |
| 睡眠 | 每晚主睡眠时长；展开后可切换入睡与起床时间 | 时长折线、作息区间图 | 对应字段实际可取得；主观休息感受和设备质量指标分别标明来源，不合成分数 |
| 运动 | 已记录运动分钟数、运动天数 | 按日柱状图，按周汇总 | 同一运动记录去重；明确计入哪些活动，避免把步数自动换算成运动分钟 |
| 饮食 | 已记录餐次、已确认的食物类别出现情况 | 餐次记录矩阵、食物类别条形图或按周变化 | 只描述已记录且可判断的餐次；未知类别、未确认识别和已确认内容分别表示 |
| 工作与学习 | 已确认的成果、实践和应用记录 | 关键成果时间线；需要时按周展示已记录实践次数 | 以具体记录为依据，不用笔记数量或文字长度表示成长；明确记录时长后才展示时长趋势 |
| 行动实验 | 当前选定行动、执行记录、到期回看和观察结果 | 状态列表；有对应指标时附前后趋势 | 不生成综合完成分；已执行、未执行、尚未到期和未知分别呈现 |

饮食每个类别按“出现／确认未出现／无法判断”记录。类别比例的分母仅包含该类别可判断的已记录餐次，并显示分子、分母和覆盖范围；同一餐中的重复照片不重复计数。第一版默认优先展示出现次数，避免局部照片被解释为全天摄入量或营养达标率。

### 时间、交互与比较

- 提供最近 7 天、30 天、90 天切换。7 天和 30 天以日为基本粒度，90 天可按周汇总；周、月复盘内嵌相同口径的相关趋势。
- 最近期间可以包含当天，但尚未结束的日或周明确标为进行中。对比采用前一个等长窗口；进行中的自然周只对比上一周相同已过去的天数，不与完整一周混算。
- 点选一个图表点、柱或餐次，进入对应日期或期间，查看参与计算的记录、来源和计算说明，再进入原文或附件。
- 可以在趋势上标注用户选定的行动开始时间与回看时间，便于结合经历理解变化；前后变化描述不自动推断因果。
- 数据来自不同量纲时使用各自图表或对齐的独立图表；不用任意加权合成“健康总分”或“成长总分”。

### 数据可信度与计算规则

1. **缺失、零、未连接和同步中不同。** 未记录或未成功同步的日子不补零，折线在缺失处断开。运动为零需完整来源覆盖或用户明确确认，没有运动条目本身不足以判断为零。
2. **原始值与计算口径可核对。** 指标定义保存稳定 ID、版本、单位、来源选择、去重规则、时间归属、聚合方式、分母和缺失规则。AI 解释已计算的数据，不自行生成图表数值。
3. **平均值只针对有效观测。** 展示有效样本数和期间覆盖；没有有效观测时显示未知。睡眠主记录按起床日归属，午睡单独标记；跨午夜的作息区间连续绘制，不能把零点两侧误判成相差一天。
4. **比较保留相同口径和覆盖说明。** 来源、单位或含义变化时分开展示或注明不可比。每日测量在等长完整窗口均有逐日有效数据时可直接作全周期比较；不完整窗口展示已观测统计与样本，不生成全周期改善或下降判断。餐次和事件数据仅比较明确的“已记录样本”，不推广为全部生活行为。
5. **估计与主观值标明性质。** AI 估计、用户自评和设备记录分开展示；只有采用同一明确量表的自评才画同口径数值趋势，不从自由文本猜出情绪或睡眠质量分。
6. **口径与证据保留版本。** 复盘引用指标时保存当时的口径、数据范围、样本、计算值和来源修订；纠错后当前图表更新，历史分析可以核对其当时依据。导出保留口径及结构化依据，使其他 AI 可以理解和重建指标。

## 9. 长期个人画像

画像用于理解“我重视什么、通常如何行动、在什么情境下发挥得好，以及正在怎样变化”。完整设计及研究边界见[长期个人画像设计](2026-10-16-long-term-personal-profile-design.md)。

按八个维度组织：价值与方向、角色与背景、兴趣与偏好、行为与决策模式、能力与有效策略、精力压力与恢复、关系与协作、人生叙事与变化。每个维度区分长期倾向、情境模式和近期状态。这是结合研究与产品需求的分类，不是标准人格量表。

画像条目引用已有观察或洞察的指定修订；陈述及其支持、反例、成立情境、时间范围和资料覆盖由共享观察／洞察维护，画像保存分类、采用状态和反馈关系。自述和行为推断分开，用户认可不等于新增证据。宽泛的身份与价值归因未经核对时留在候选区；范围明确且有来源的观察与情境洞察可自动整理，后者标明 AI 推断与核对状态，日常记录无需等待逐条确认。

新资料、纠错、来源删除或生活情境变化触发相关条目复核；默认建议周复盘检查近期模式、月度查看画像变化。这样的周期是维护安排，不是“记录满 30／90 天即可确定人格”的承诺。已明确否定的判断不能通过反复重写自动回到当前画像。

## 10. 分层检索与维护可靠性

强制采用四层索引与原始证据层：入口 → 领域 → 时间／情境范围 → 证据目录 → 原始记录或可复算指标。各入口共同引用稳定 ID，允许受控跨分支和精确定位，避免分类错误使资料永久遗漏。

读取流程为：建立计划与快照 → 路由并枚举范围 → 按预算分批读取 → 保存有引用的中间成果 → 核对覆盖与语义支持 → 提案校验后发布。全周期统计由程序处理完整目标集合，模型接收结果与必要证据；文字全周期分析分批处理，检索排序不能悄悄排除未分类资料。

分别报告生活记录覆盖、取证范围覆盖和处理覆盖，细化到原文片段和附件；时间未知的资料单列缺口。最终新结论核对实际原文、重要反例或确定性计算结果，不能只检查中间摘要。流程完成不等于语义判断必然正确，引用可达也不等于引用支持结论。执行层保证流程与维护一致性，分析质量通过可核对任务、反例、来源校验和用户纠正持续评价。

详见[分层检索与维护可靠性协议](2026-10-16-knowledge-routing-and-reliability-design.md)。接入本 App 检索接口的 AI 可受到相同约束；纯文件外部 AI 只能得到文档约定，无法仅靠 README 技术强制。无读取工具的 AI 使用按任务生成的有限证据包，并保留范围限制。

## 11. 第一版的设计范围与验证标准

内容分为五个相互衔接的工作包：

1. **记录与知识底座**：自由记录、稳定身份和修订、分层交叉索引、受控路由与证据包、来源快照与增量失效、校验发布、知识包生成与恢复。
2. **复盘与行动闭环**：内置模板、个人模板导入、日/周/事件复盘、带证据的分析、行动回看。
3. **关键数据看板**：统一指标口径、核心趋势卡片、期间切换、记录下钻和行动回看，复用已有记录与复盘的证据关系。
4. **丰富输入**：餐食拍照识别与指南分析、经验证的华为睡眠运动同步，接入同一内容模型和看板。
5. **长期个人画像**：维度组织、情境与时间分层、证据及反例、用户修正、画像变迁和可迁移发布；从已有记录逐步形成。

这五个工作包均属于第一版设计范围，阶段依赖、实施顺序和完成状态统一由[开发路线](../../ROADMAP.md)维护。华为接入仍需核实个人开发者资格和目标字段；模型供应商、数据处理位置和真实设备授权在对应实现设计中确定，本草案不据此承诺接入已经可用。画像的组织与修正能力属于第一版，长期内容的完整程度取决于实际资料积累。

验收场景：

- 从个人概览定位一条睡眠判断，能继续定位对应一周、某天和原始记录；不同入口指向相同身份。
- 同一条记录关联工作与睡眠时不复制原文；补记上周事件归入正确周期。
- 周报生成后补记上周事件，相关周报及当前主题结论进入待更新状态；重算后包含新增依据与新的覆盖说明。
- 修正一条记录后，受影响的当前结论标明待更新，更新后来源引用正确，用户已确认的文字仍保留。
- 只有两餐照片时，分析明确覆盖两餐；缺失记录不自动转成饮食或成长的负面判断。
- 导入个人模板可以预览、修改和保存；模板升级后旧复盘仍显示旧问题与答案。
- 归档和删除具有不同结果；删除记录后，新导出的原文、旧修订与派生摘录中不残留被删除内容，相关历史引用明确标记来源已删除。
- 一份周复盘能定位至少一个结论的具体证据，并回看上周用户选定的行动；证据不足时允许不形成结论。
- 看板默认只显示 3 个主要趋势卡片及行动回看区，支持调整关注项、切换期间，并从图表定位参与计算的记录。
- 7 天中只有 4 晚睡眠数据时，缺失日期不画为零，均值标明基于 4 晚，且不将其描述为完整一周的睡眠均值；午夜前后作息显示连续。
- 看板与同一周期复盘的数值、样本和口径一致；补记、更正、删除或同步修订后，两者更新并保留必要历史依据。
- 两餐照片仅支持两餐的类别出现情况，重复照片不重复计数；图表不推算全天热量、营养达标或综合健康分。
- 指标来源或模板量表改变时不静默接续为同一条可比较趋势；进行中的一周不直接与完整上一周比较总量。
- 画像中的描述能定位时间、情境、支持和反例；同一事件的多次总结不构成多份独立证据，近期状态不自动升级为人格结论。
- 用户否定或限定某条画像解释后，当前摘要更新，后续处理相同资料不会静默恢复旧判断；自述与实际行为差异保留背景和未知原因。
- 当前画像、历史版本和候选解释范围明确；删除来源后相关画像内容遵循清理与重算规则。
- 全部 AI 分析调用都有计划、读取预算、版本与证据登记；模型请求超预算时拆批或报告未完成，不能绕过协议读全库。
- 全周期任务能核对取证与处理范围，未分类资料和失败附件明确计入缺口；定量结果来自完整合格数据，而非语义检索的少数命中。
- 生成期间发生相关纠错或删除时旧任务不能发布为当前结果；保存后退出可恢复任务，重试不产生重复内容。
- 模型失败时记录可用，重试不重复生成记录；文档生成失败不把不完整的新包发布为当前包。
- 在另一份空存储中恢复完整迁移包，资料、模板版本、附件与引用完整；只读文件的 AI 可以沿目录找到指定事件，无需先读所有内容。
