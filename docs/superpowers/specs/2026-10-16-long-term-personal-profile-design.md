# Trace Life：长期个人画像设计草案

日期：2026-10-16。状态：完整产品目标；已实现范围与验证见[开发路线](../../ROADMAP.md)。采用与维护、受控候选生成及[跨任务维护](../../PROFILE_MAINTENANCE.md)按阶段交付，不等于本文件全部目标已完成。

本文件细化[主设计](2026-10-16-personal-knowledge-and-reflection-design.md)中的个人画像。画像回答“我重视什么、通常如何行动、在什么条件下发挥得好、正在怎样变化”，并为复盘和行动提供背景。它随证据积累而更新，保留情境、例外和历史版本。

## 1. 研究依据与产品判断

| 研究依据 | 本次核实到的内容 | 对本设计的启发 |
| --- | --- | --- |
| [McAdams & Pals：整合人格框架](https://pubmed.ncbi.nlm.nih.gov/16594837/) | 原论文摘要包含特质、特征性适应、人生叙事及文化社会情境 | 同时理解长期倾向、目标与应对方式、经历和生活背景 |
| [Schwartz：基本价值观](https://scholarworks.gvsu.edu/orpc/vol2/iss1/11/) | 作者发表页区分价值与特质，并讨论价值优先级及冲突 | 把“重视什么”单独保留；并列呈现理想、选择及其情境 |
| [Soto & John：BFI-2 原始研究](https://www.colby.edu/wp-content/uploads/2013/08/Soto_John_2017.pdf) | BFI-2 通过实际问卷作答测量五个人格领域及其子维度 | 正式测量结果与日常记录推断分别标注；不把 AI 日记分析称为有效量表得分 |
| [Fleeson：人格状态的分布](https://simine.com/407/readings/Fleeson_2001.pdf) | 体验抽样中存在显著个体内状态变化，同时分布的一些特征较稳定 | 描述“通常怎样”时同时保留“什么情况下不同” |
| [Fisher 等：群体与个体推断](https://escholarship.org/uc/item/75k4x9xf) | 重复测量资料中的群体与个体内关系可能不同 | 个人结论要检查本人的纵向资料；群体规律仅作为解释背景 |

这几项研究没有共同验证一个自动画像算法，也没有给本 App 提供通用的记录天数阈值。下文的八个维度、文件组织、更新规则和复核节奏均属于产品设计综合，不能称为标准心理量表。研究阅读范围、限制与来源见[框架调研](../../research/2026-10-16-personal-profile-frameworks.md)和[纵向证据调研](../../research/2026-10-16-longitudinal-profile-evidence.md)。

## 2. 画像保留的八个维度

维度用于查找与组织，不要求每天填写或一次补齐。尚无材料的部分保留未知。

| 维度 | 回答的问题与沉淀内容 | 主要依据与范围 |
| --- | --- | --- |
| 价值与方向 | 我重视什么，希望成为怎样的人，重要目标如何取舍 | 用户表达、决定及其理由；自述价值与行为观察分别呈现 |
| 角色与背景 | 当前承担什么角色，有哪些责任、资源和现实约束 | 用户提供的工作、家庭和阶段背景；注明适用时间，不自行猜测 |
| 兴趣与偏好 | 什么值得持续投入，喜欢怎样交流、获取信息或安排活动 | 明确偏好与重复选择；偏好不等于能力，也不构造固定“学习类型” |
| 行为与决策模式 | 怎样开始、坚持、调整、学习和作决定；什么条件有帮助 | 具体事件中的情境、行为、结果与反例；学习方法效果按实际场景描述 |
| 能力与有效策略 | 哪些能力已有实践依据，哪些方法有效，哪些仍在探索 | 成果、作品、练习、应用与行动回看；收藏数量不代表熟练度 |
| 精力、压力与恢复 | 生活节律、压力情境、睡眠运动饮食与主观感受怎样共同变化 | 设备观测与自述分开；睡眠等数据支持生活模式，不单独推出性格 |
| 关系与协作 | 沟通需要、支持方式、合作偏好和个人边界 | 用户主动提供的互动与体验；结论限定于用户及已记录情境 |
| 人生叙事与变化 | 哪些经历重要，哪些认识发生变化，如何理解转折 | 用户原话、重要事件与画像历史；事件的个人意义由用户表达或确认 |

五大人格等规范测量可作为将来的补充背景，不是第一版必须内置的测评模块。第一版的记录功能可保存用户主动提供的测量结果，但必须注明它是用户提供的信息；不能据此宣称本 App 完成了测量、计分或效度验证。内置题库需另行核验准确版本、适用语言、授权和解释依据。

## 3. 每个维度都区分时间与情境

| 层次 | 内容 | 可接受的表达 |
| --- | --- | --- |
| 长期倾向 | 用户明确陈述的长期偏好，或跨周期重复且经核对的倾向 | “你表达过重视自主安排；在已记录的这类选择中也出现这一考虑。” |
| 情境模式 | 仅在明确条件下出现的行为、体验或有效策略 | “在任务边界不清楚的记录中，启动困难更常被提到。” |
| 近期状态 | 当前阶段的目标、关注点、精力与生活变化 | “近期已记录的工作日里，晚结束工作更频繁。” |

以上是表达示例，不是对当前用户的判断。长期不等于永久，最近出现的行为也不自动成为长期倾向。当前角色和约束可以解释模式何时适用；用户进入新项目或人生阶段时，相关条目应重新检查。

用户的直接声明可以立即保存并注明“个人自述”。由行为形成的概括需交代实际覆盖的时间和情境；自述认可、观察重复性和正式测量是不同证据，不互相替代。

## 4. 如何分析：逐条积累可核对的理解

本节全部步骤受[分层检索与维护可靠性协议](2026-10-16-knowledge-routing-and-reliability-design.md)约束。先确定任务和来源快照，再通过领域、时间／情境及证据索引分批取证；不能把全部日记或完整画像历史一次送入模型。跨周期综合保留原始事件、反例和处理覆盖；路由索引与旧画像仅作定位和背景。

1. **整理来源。** 从已有记录提取用户说了什么、发生了什么、当时情境与结果，保存原句引用和时间。不额外猜测动机；同一事件的随记、日复盘和周摘要只算一个原始事件。
2. **检查可见范围。** 记录哪些日期、情境和维度有资料。只在不顺利时写的随记不能代表全部生活；文本中提及某事的次数不直接等于行为频率。
3. **先描述观察。** 看板指标按统一口径计算；文字材料按事件和主题检索，归纳具体行为、实践和感受。已有画像和周报可帮助定位，但不充当新的独立证据。
4. **提出候选模式。** 在不同时间段查找重复情况，同时查找反例、例外和替代解释。只在某类项目中出现的现象保留项目情境，不外推到所有生活领域。
5. **使用新资料回看。** 后续记录可支持、缩小或否定先前解释。不能总在最初的一批资料里反复挑选支持例子，也不能只按数量累计强化早期印象。
6. **更新少量画像条目。** 更新受影响的具体描述和依据，生成变更说明，再由这些条目生成概览。缺乏资料的维度不自动填满。
7. **连接复盘与行动。** 某个模式有助于当前目标时，可提出小行动。用户采纳后记录预期与回看方式，实际结果成为新的证据；变化本身不自动证明因果。

支持关系保存“记录中的陈述、设备观测或估计”各自的来源类型。证据说明展示观察跨度、独立事件、情境分布、反例和缺口，不输出模型自报的“人格置信度 93%”。第一版优先采用可追溯描述，不输出未经单独验证的心理得分或因果系数。

## 5. 画像条目与已有知识的关系

**观察和洞察保存陈述、证据及成立的情境和时间范围，画像条目保存如何组织与使用这些陈述。** 同一个判断不在主题档案、画像和概览中独立维护三遍。用户自述引用观察，AI 解释引用洞察；画像条目指向指定修订版本，阅读视图展开所需内容。用户修改陈述或缩小成立范围时修订共享观察／洞察，画像采用新修订，主题档案和概览同步更新。

| 字段组 | 保存的信息 |
| --- | --- |
| 身份与内容 | 画像条目 ID、修订版本、所引用观察或洞察的 ID 与版本 |
| 组织与采用 | 所属维度、长期／情境／近期层次、在画像中的采用起止时间；陈述成立的情境和时间范围继承自被引用修订 |
| 证据说明 | 从被引用陈述取得支持与反例引用、原始记录修订、独立事件与覆盖、替代解释和未知项 |
| 用户反馈 | 未查看、认可、限定情境、不同意或补充背景；反馈原文与时间 |
| 状态 | 画像采用状态为候选、当前采用、已被替代或不采用；陈述的有效／待复核／撤回状态由共享观察或洞察维护，后者失效时所有当前入口同步失效 |
| 维护信息 | 首次形成、最近有支持的时间、最近复核时间、来源与生成方法版本 |
| 变化与使用 | 上一版本、历史有效期、相关目标与行动实验、下次复核触发条件 |

证据链接在被引用的观察／洞察修订中维护，画像不复制另一套可独立修改的证据。历史发布版本引用固定修订，当前画像选择符合有效状态的版本。

### 用户反馈与自动维护

- 原始自述、范围明确的观察和有来源支持的情境洞察可以自动整理进入当前画像；情境洞察仍标为“AI 推断”，未经用户查看时标为“未核对”。AI 候选解释可自动生成，记录流程无需逐条等待确认。
- 对价值排序、人生意义和跨情境身份的概括，提供“符合／仅限这个情境／不符合／补充背景”。未经用户核对的这类解释保留在候选区，不进入默认的当前身份摘要。
- 用户认可表示这条描述可用于理解自己，不等于科学验证或新的独立行为证据。缺少行为支持时仍显示其原有来源性质。
- 用户指出原始资料错误时修正记录；指出解释错误时撤回共享洞察，各当前入口同步更新；指出适用范围过宽时给共享陈述生成更窄的新版本。仅不希望某条有效内容用于画像时，改变画像的采用状态，不将原陈述标成错误。原始资料不因解释被否定而自动删除。
- 再次生成时读取既有反馈。被明确否定的同一判断不能仅因模型换了措辞就恢复；有新的独立证据时，只形成带变更理由的新候选。

### 自述与行为不一致时

并列保留“用户重视的事情”“记录中可见的选择”“已知条件及未知原因”。例如自述重视学习，而近期学习记录较少，可能涉及工作约束、阶段取舍或记录缺失；画像先保留差异，复盘时再理解。不能直接改写成“你其实不重视学习”。

## 6. 更新、变化与过期

- **记录变化时**：纠错、补记、删除、来源变化和新反例触发相关条目复核；既检查直接证据依赖，也检查原时间／情境范围内新增的资料。
- **每周**：整理近期状态和候选模式，供周复盘使用。日常记录不必立刻改写整个长期画像。
- **每月**：建议生成一次画像变化摘要，说明哪些描述新增、范围缩小、获得新支持或不再适用。这是可配置的维护安排，不是人格测量所需的科学时间阈值。
- **阶段变化时**：用户更新角色、目标、工作环境或重要约束后，检查受影响的旧模式，不默认跨阶段成立。
- **没有新资料时**：显示最后得到支持和复核的时间。缺少新支持不等于已经错误，也不等于仍然适用；被问及超出历史范围的情况时明确资料边界。
- **来源被删除时**：遵循主设计的删除规则，撤掉相应依据并复核结论；历史画像、摘要及导出中复制的已删除来源内容需要清理，不能借“保留历史”继续传播。

近期状态必须显示其时间范围，默认近期窗口移出后不再作为当前状态。长期条目在证据变化或情境不再适用时更新，不因到了某个天数自动变成人格定论。7／30／90 天只是查看窗口。

## 7. 知识库中的沉淀与读取

完整知识包增加以下固定位置；文件按已有资料生成。维度正文和历史页是阅读视图，不成为第二份可独立编辑的主数据。

```text
profile/
  index.md                       # 当前摘要、维度入口、覆盖和最近复核时间
  values-and-direction.md
  roles-and-context.md
  interests-and-preferences.md
  behavior-and-decisions.md
  abilities-and-strategies.md
  energy-and-recovery.md
  relationships-and-collaboration.md
  narrative-and-changes.md
  history/
    index.md
    2026/10.md                   # 当月变化与发布版本入口
data/
  profile-entries.jsonl          # 条目及修订，引用观察／洞察
  profile-releases.jsonl         # 发布版本、采用条目版本和变化说明
```

- `overview.md` 在完成全局入口和任务路由后按需读取，链接当前画像及近期状态；不要求外部 AI 一次读取所有维度。
- `profile/index.md` 概括当前可用的自述、范围明确的观察和情境洞察，以及已经用户核对的宽泛身份解释，标明各自性质、核对状态与覆盖。需要理解某一方面时再打开对应维度。
- `topics/` 回答某领域发生了什么；`profile/` 回答这些资料对理解用户有什么帮助。两者引用相同观察、洞察及原始记录。
- 历史版本、未核对的宽泛身份解释、被撤回的判断不混入默认当前摘要；用户或外部 AI 查询历史或候选时，仍能在状态明确的专门范围找到它们。
- 整包导出保留结构化条目、修订、反馈与关联。恢复时可以重建当前和历史画像，原始来源删除的处理仍优先于恢复旧描述。
- 文件入口说明读取协议；本 App 的检索接口才可强制范围、预算与版本控制。无文件或工具读取能力的外部 AI 使用带覆盖说明的任务证据包，不能宣称自主查阅了全库。

## 8. 第一版实现范围与验收

第一版提供八个维度的组织结构、从记录形成候选描述、证据与反例查看、用户修正、按情境分层、当前摘要和历史变化。资料从首条记录开始积累；长期模式随覆盖增加逐渐形成，不承诺使用满固定天数后画像一定完整。

验收场景：

- 一条关于个人的描述可以定位到具体来源、时间范围、支持与反例；从多个入口找到的是同一条陈述。
- 单次晚睡可以进入近期记录，但不会自动生成“缺乏自律”的身份结论；只在某个项目中出现的模式保留项目限制。
- 同一事件在随记、日报和周报中出现，不被计算为三个独立支持事件。
- 用户自述的价值与近期行为有差异时，页面保留二者及已知背景，不擅自决定哪一个是“真正的你”。
- 用户缩小或否定一个解释后，当前摘要更新；再次分析同一资料不会静默恢复原判断。
- 用户缩小陈述范围时，主题档案与画像引用同一新修订；仅取消画像采用时，其他入口仍可显示有效的原陈述。
- 范围明确且有来源的情境洞察可以自动显示并标注 AI 推断、未核对；宽泛身份解释未经核对保持候选，二者不使用同一确认门槛。
- 行为候选、用户认可、证据重复性与规范量表结果有不同标记；用户点击认可不会产生新的观察或心理得分。
- 工作环境改变后，旧情境模式被标记复核；历史版本仍能说明当时为什么采用它。
- 删除支持资料后，当前、历史阅读视图和新导出遵循删除与重算规则，不留下被删来源的复制内容。
- 某个维度没有记录时显示未知；读取当前画像不需要加载全部日记，也不会将候选或撤回内容误当当前定论。
- 画像更新按计划分批取得证据并检查反例，未完成的范围明确保留；仅呈现既有画像与重新分析形成新判断分别标明。

真实使用时还需检查：证据引用是否正确、描述是否超出资料、反馈后错误是否停止重复、画像是否有助于具体决策。用户觉得“很像自己”不能单独验证其准确性。
