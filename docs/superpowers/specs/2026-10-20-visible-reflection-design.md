# Trace Life：记录后的分析与沉淀闭环

## 要解决的问题

用户能保存记录，但首页没有明确的分析入口，也无法知道分析是否执行、覆盖哪段时间、留下了什么经验或发现了什么问题。原「整理」页面主要执行片段提取，知识库只展示分类、日期与状态；已有周期综合接口尚未形成手机上的完整操作流程。

本轮沿用现有原生单色页面，将主动分析、结果阅读、来源核对和知识收录串起来。按用户已经明确的记录与分析需求实施，不增加聊天入口，不使用记录数量推断成长，不强行生成不足。

## 用户操作

1. 首页在记录入口之后显示「分析与发现」，提供明确的「分析记录」按钮；有历史任务时显示最近范围、状态和结果入口，没有时说明记录尚未通过这个入口分析。
2. 分析页可选今天、最近 7 天、最近 30 天或自定义范围，默认最近 7 天。开始前说明本次选中原文将发送给 DeepSeek，可能产生费用及每轮请求上限。
3. 用户点击后执行跨记录综合；超出单次输入预算时分批，再逐层归并。页面展示实际阶段、已处理范围与剩余进度。中断、失败、额度不足和来源变化分别显示，不用假百分比，也不把部分结果说成全部完成。
4. 结果直接呈现「值得留下」「值得关注」「可以尝试」及资料缺口。只按输出中明确的栏目前缀组织；格式不匹配的内容显示为其他发现，不依关键词猜测用户的不足。任一栏目可以没有结果。
5. 每项发现保留原文入口。用户可否定，或明确确认后继续核对并保存到知识库；确认、模型支持和正式保存分别呈现。核对失败或证据不足时不能发布，确认不构成证据。
6. 分析历史从持久任务台账恢复；返回页面、旋转或重启可查看结果或明确继续，不能因此重新收费调用。来源变化的历史结果标注待更新，不冒充当前判断。
7. 知识库显示正文摘要，并提供发现、经验和观察分类入口；待更新的历史内容有明确入口。知识库也能直接启动分析。

## 技术边界

- 使用现有 `ControlledAnalysis`、`PeriodSynthesisProcessor`、`PeriodReductionProcessor`、`PeriodReductionReviewProcessor`、反馈和知识发布接口。单批综合与多批归并的目标类型分别处理，不拿局部核对代替整体核对。
- 新增应用编排模块管理共享的每轮请求上限和页面状态；分析内容仍保存于现有任务台账并进入已有备份，不额外将正文复制到偏好设置。
- 保留索引路由、快照、字段分片、累计预算和原文登记。所有模型请求继续通过受控执行层。
- 页面摘要是受信任本地读取，每页有上限，不转交模型作为无限制知识库读取接口。
- 资料不足、未解析图片、未知日期等原有覆盖缺口持续显示。用户反馈与已有失效规则保持有效。
- 首轮接通主动周期分析与发现保存；后续持续积累的约束见下一节。自动主题识别、完整主题档案和纵向画像维护仍按各自设计推进，不能因新增分析按钮宣称这些能力完成。

## 评审后的持续积累优化

2026-10-20 用户要求按[用户旅程评审](../../reviews/2026-10-20-user-knowledge-journey-review.md)重新优化。本次复用已有受控分析、知识、行动及数据转移模块，先保证保存、删除、当前性与交付正确，再连接主题中的经历和尝试。只改变页面无法解决错误清理；更换数据库或重新搭建知识引擎也不是这轮的必要条件。

### 保存和有效性分开

「已保存」表示存在持久知识身份；「待更新」表示该内容的依据或适用条件需要重新检查。旧知识失效后仍可读、可定位原身份，不退回「尚未保存」，也不显示为当前结论。首页分别显示保存数量及其中待更新数量。知识默认阅读区保留待更新条目，并明确标记；面向外部的当前知识包继续只包含有效条目。

来源有效性按原任务范围判断：保留原始来源戳，通过程序记录的变更范围判断其后的修改是否影响任务。不同日期的无关新增不使旧任务失效；补记到目标期间、日期从旧范围移至新范围、未知日期资料、精确 ID 与归档条件分别处理。不能用主题不同推断同一期间资料无关，也不能把旧戳替换成新戳来伪装重新分析。升级前缺乏变更历史、备份恢复和台账缺口均保守失效，不能猜测旧任务重新有效。全库代数仍用于一次读写、分页和导出快照的一致性检查。

永久删除沿真实取证回执、完整统计来源、归并祖先及画像维护引用传播，清理受影响的机器文字与历史；无关知识、修订和用户独立文字保留。只因范围重叠但尚未读取正文的任务进入待更新，不凭空认定存在必须擦除的摘录。删除未使用模板不清空知识库。恢复旧备份同样尊重依赖和已知删除决定。

### 主题、经验和行动

知识库提供现有主题入口、各主题的保存内容及按时间分页的原始经历；同条多主题记录始终定位同一身份。主题数量、范围及最近内容由程序计算，不能将目录统计伪装成模型归纳的主题理解。没有填写主题的内容保留可达入口。主题别名、同义经验合并、适用条件演化与反例关系仍是后续工作，不把筛选页称为完整主题档案。

用户从「值得留下」保存的内容，在「经验」阅读入口可以找到；底层仍保留它是可能解释的证据性质，不为配合页面名称伪装成事实或知识材料。

发现经确认与核对正式保存后，可选择「据此尝试一个行动」，展示来源参考，由用户填写具体计划、触发条件、观察信号及回看日期。来源引用固定知识版本并验证当前性；知识可查看关联行动，行动可以回到知识及记录回看。未保存或已失效的发现不得伪造有效行动来源。下一次普通文字分析自动读取行动证据，属于另一个需受控接线和验证的步骤。

### 手机上的文件交付

文件必须先在应用私有目录完成生成、完整性与快照校验，再通过系统「另存为」交给用户。取消选择、应用重启或外部写入失败后，完整本地副本可以再次选择位置。外部副本写入、关闭并重新读取校验成功后才提示保存完成。失败尝试清理不完整副本；文档提供方拒绝删除时需告知用户，不能声称外部文件一定不存在。

Android 实际文件系统拒绝硬链接时，不得用普通复制替代原子发布。保留任意 `File` 目标的无覆盖契约；手机导出使用独立、私有、排他的目标目录，在原有事务与版本校验内原子发布已经完整生成的文件。所有权和完成状态受程序控制，未完成目录不作为可交付文件。该保证不扩展到第三方文档提供方；系统另存的验证单独说明。具体接口及格式见[数据转移](../../DATA_TRANSFER.md)。

### 本次验收与后续范围

- 无关记录新增、删除及未使用模板删除保留其他知识；相关补记、改日期、未知日期及删除分别触发必要失效或清理，恢复和导出行为一致。
- 旧版数据库原地升级不丢资料；升级前已经失效的知识仍可见，但不能被自动认定有效。
- 首页保存数、发现详情与知识库一致；「经验」能找到刚保存的方法；主题进入同一原文，知识和行动双向可达。
- 实际 Android 上导出、系统选址、重新读取文件和重启后再次另存可用；自动化覆盖取消、截断、校验失败和并发变更。
- 长期任务归档、跨任务反馈继承、同一经验的演化身份、完整画像维护旅程及主题概况层不因本次完成而被标为已实现。它们继续按评审中的独立验收要求推进。

## 验证

- 合成原文触发实际综合调用，多个批次进入归并，单轮请求上限跨阶段共享；失败、中断、空结果及重启恢复保留真实状态。
- 未确认的发现不能正式保存；确认后重新读取依据，否定阻止发布；单批及归并发现分别验证。
- 首页按钮进入分析范围选择，结果页能查看内容和依据，历史任务重新打开不发起模型请求；旋转恢复任务与范围。
- 知识库显示正文而非只有元数据；当前与待更新条目清楚区分，分页没有丢失观察入口。
- 运行相关行为测试、全量单元测试、Android lint 与 APK 构建。真实 DeepSeek 质量、模拟器和实体手机验证单独报告；本轮不自动重新开启用户已关闭的模拟器。
