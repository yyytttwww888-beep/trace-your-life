# 主动分析与发现保存

手机上的「分析」入口串联跨记录综合、分层归并、来源查阅及确认后的知识保存。交互目标见[本轮设计](superpowers/specs/2026-10-20-visible-reflection-design.md)，原文与派生内容的边界沿用[综合接口](SYNTHESIS_ACTIONS.md)、[分层归并](PERIOD_REDUCTION.md)及[周期核对](PERIOD_REVIEW.md)。

## 使用流程

首页「分析记录」进入日期选择，支持今天、近 7 天、近 30 天与自定义日期；记录详情和回顾页面也能带着日期进入。点击「开始分析」并确认本次在线调用后执行，一轮最多 5 次请求。普通「逐条整理」仍保留片段提取入口，两种操作分别保存任务。

结果按明确前缀显示值得留下的经验、值得关注的问题、可以尝试的改进；格式不匹配的内容留在其他发现。模型可以返回空结果，页面不根据记录缺失自行评价用户。部分综合结果会标明尚未完成，整合完成后才提供确认和保存。

点击一条发现可查看其生成批次的原文与上下文，分页阅读；多批成果沿完整来源链读取。选择「保留到知识库」表示用户确认，随后独立重新核对原文；只有最新核对支持时发布为洞察。保存对话框带入实际来源记录已有的主题，用户可调整或清空；不会由页面猜测新的分类。否定不会被自动覆盖，单批多条发现可分别处理。原文变化、删除、反馈变化和超预算继续遵循原协议。

发现详情与对话回答共享保存流程；有效确认和已完成的支持核对可以复用，已保存内容不重复发布。保存后直接提供加入经验线索与建立行动，打开下一步前重新解析当前有效的知识修订。历史意见未完成或存在冲突时，仍须先对照处理，聊天赞同不代替正式确认。

分析历史分页读取现有台账，旋转、返回和重新打开只读进度，不启动付费请求。中断恢复和重试分别由用户触发。首页展示最新分析范围、状态、发现数量、持久保存数量及其中待更新数量。发现已有知识身份后，来源或反馈变化仍显示「已保存 · 待更新／已否定／已纠正」，可以进入同一知识条目与后续尝试；这不允许继续采用失效结果。

知识库默认展示保存过的当前修订及明确的待更新状态，提供发现、经验、观察与全部条目。严格以「值得留下：」开头的已保存洞察也出现在经验入口，底层仍是可能解释。已有主题连接知识、原始经历与具体记录修订，细节见[主题阅读](KNOWLEDGE.md#手机主题阅读与后续尝试)。

当前有效知识可以作为用户行动的真实来源：页面只展示发现供参考，用户明确填写并保存计划才算采纳。知识详情可看到关联行动及回看结果，行动可回到起点知识与历史。创建行动草稿及相关阅读位置支持页面重建；这些导航和本地读取不会调用模型。

## 应用接口

以下接口在应用 IO 线程调用，页面正文读取不开放给模型。

```kotlin
val run = app.reflectionWorkflow.start(AnalysisQuery(from, through, zoneId))
val pass = app.reflectionWorkflow.process(
    run.id, app.deepSeekProvider, maxRequests = 5,
    onProgress = { current -> /* 每次持久化进度后通知页面 */ },
)
val current = app.reflectionWorkflow.inspect(run.id)
val history = app.reflectionWorkflow.history(limit = 20, offset = 0)
```

`ReflectionRun` 返回状态、固定范围、文字覆盖、综合与归并批次数、累计请求、发现及缺口。统一问答还返回已有理解的提供情况及行动事件总数／已处理数，分别展示背景与原始证据覆盖。`canReviewFindings` 表示当前最终结果可逐项处理，不代表任何发现已成立。`ReflectionPass.status` 还可能携带本轮预算或冲突状态，页面必须显示它，不能只显示 `run.status`。

`ReflectionFinding.knowledgeId` 表示仍存在的持久知识身份，`knowledgeEvidenceState` 单独表示当前证据状态；保存计数不能只计算 `CURRENT`，继续核对／发布也不能只判断 ID 是否存在。`suggestedTopics` 按实际来源记录的元数据提供至多 30 个已有主题，需用户明确确认。

`respond` 与 `reviewAndSave` 分开：前者需要用户实际查看的任务版本、目标身份及反馈版本，后者要求有效确认，沿普通原文核对或归并扫描／最终核对继续。生成阶段不发布、不自动确认、不采纳行动。`evidence` 只返回分页引用，`original` 限于登记片段，检查范围、版本及完整片段哈希；`actionEvidence`／`actionOriginal` 分别定位已登记的固定计划与回看，不把后来的计划替换成当时的执行情况。

任务使用 `reflection-v1-` 身份，保存在既有分析台账，沿现有完整备份保存；历史识别按该前缀并排除画像任务，包含自动纳入行动的对话任务，不依赖问题正文完全相等，调整提示词不会隐藏旧记录。独立行动周期入口保留自己的任务身份与历史。工作流不另复制任务或正文；来源范围台账自 schema v9／备份格式 v8 引入，当前格式及兼容策略见[数据转移](DATA_TRANSFER.md#完整恢复备份)。

## 当前边界

- 快捷周期分析读取所选范围文字；日期表单的「结合行动与实际回看」进入完整行动复盘流程，保留日期、时区、归档及指定记录范围。[对话式回看](CONVERSATION.md)会自动识别范围内行动，并提供有界的已有理解背景。行动取证规则见[行动周期分析](ACTION_PERIOD_REFLECTION.md)。
- 用户选择保存的经验性解释仍按洞察协议发布，可从经验入口找到；主题概况汇集已有知识与行动，主题／经验候选经用户确认才建立关联，不自动合并。详见[知识导航](KNOWLEDGE_DISCOVERY.md)。
- 来源戳保留原值，以范围变更台账判断是否受后续资料影响。范围外无关新增不使旧任务失效，范围内补记等仍需重新分析；升级前已失效内容不会自动恢复为有效。没有自动重算；跨任务历史意见继承与辅助比较遵循下节协议。
- 活动任务最多 100 个，已归档任务另有数量及字节上限；达到容量明确失败，不自动删除历史。详见[任务归档](TASK_ARCHIVE.md)。
- 结果质量受实际输入和模型影响。分批完成、引文可达和模型核对均不能替代真实使用评估。默认只处理文字，图片及健康数据缺口如实保留。

## 验证入口

`ReflectionWorkflowTest` 检查实际综合与归并编排、请求额度、重启恢复、独立确认和否定、原文分页、主题建议及保存身份。`ReflectionActivityTest`、`MainActivityTest`、`KnowledgeActivityTest`、`ActionsActivityTest` 通过 Robolectric 检查页面行为，包括待更新保存数量、主题原文定位及行动采纳后回看返回知识；这些自动测试不等同于实体手机验收。

显式合成 DeepSeek 验证最多 1 次综合和 1 次原文核对，普通测试默认跳过，不读取密钥：

```bash
./gradlew testDebugUnitTest --tests 'dev.tracelife.providers.DeepSeekReflectionLiveTest' \
  -PtraceLifeDeepSeekReflection=true
```

凭据使用[已有仓库外配置](DEEPSEEK.md#配置-key-后的开发机验证)。这个小样本不覆盖统一知识背景、全年资料或全部语义问题；额外测试及评审入口见[质量验收](ANALYSIS_QUALITY.md)。实际运行结果统一记录在[开发与验证](DEVELOPMENT.md)。

## 跨期积累与任务收起

普通主动分析固定相关历史意见目录，按请求预算带入最多 8 条控制背景；每条发现保存前分页逐项对照全部相关意见，有未处理或冲突则不能核对发布。界面支持直接填写纠正，显示生成参考数与对照进度。接口、范围和限制见[历史意见](HISTORICAL_FEEDBACK.md)。

分析记录按活动／归档分别分页；归档保留处理过程和知识依据，恢复不自动请求模型。归档容量、恢复语义见[分析归档](TASK_ARCHIVE.md)。已保存知识可加入[经验线索](EXPERIENCE_CONTINUITY.md)，串联后续补充与例外。

## 辅助比较与重新分析入口

发现详情可启动[历史语义辅助](HISTORICAL_FEEDBACK.md)，分批比较全部历史意见，用户查看后仅确认当前页的无冲突建议。未比较、冲突、不确定和原文核对继续独立处理。知识待更新入口带回原来的日期、时区、归档范围和指定记录；清除指定记录由用户明确操作，新任务不会覆盖旧理解或独立说明。

自由提问与连续追问通过[对话式回看](CONVERSATION.md)使用 `startQuestion`，复用这里的处理、证据、反馈与保存流程。原有快捷分析问题和入口继续保留。
